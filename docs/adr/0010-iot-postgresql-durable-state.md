# 物联网生产持久状态采用 PostgreSQL 同步高可用

自研 MQTT 服务及物联网应用需要在单节点故障后保持已确认持久接收的数据，因此物联中心生产后端采用 PostgreSQL 严格同步高可用，保存恢复所需的 Broker 状态及业务接收事实，复用数据库复制与切换，并由 Broker 实现连接归属、旧所有者隔离和协议恢复。该选择减少项目需要自行维护的数据复制机制，同时接受同步提交和关系存储的成本，遥测分区、容量与故障目标仍须实测。通用框架完整保留 MySQL、PostgreSQL、SQLite 支持，物联中心高可用交付先以 PostgreSQL 为生产后端，不将同等集群能力推定为三库共有。
