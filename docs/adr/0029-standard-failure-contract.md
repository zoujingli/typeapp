# 标准失败契约与边界响应

状态：已决定，2026-11-15

## 背景

HTTP、命令、任务和 ORM 都需要稳定错误码，但失败消息、HTTP 状态和字段明细属于不同边界。把所有异常都做成 HTTP 异常会让数据库和运行时组件依赖协议层，也会把诊断文本误当成公共接口。

## 决策

- `Type\Runtime\FailureInterface` 只定义稳定 `errorCode()`；异常消息只用于诊断，调用者不能解析消息判断业务分支。
- `Type\Runtime\PublicFailureInterface` 在失败契约上增加 `status()` 和安全 `body()`；只有 HTTP 边界异常和输入校验异常实现它。
- ORM、运行时和业务异常继续保持自己的类型和错误码，不携带 HTTP 依赖；HTTP 中间件统一转换 `PublicFailureInterface`，未知异常统一返回脱敏的 `internal_error`。
- CLI、任务和线程入口沿用同一错误码事实，各自决定退出码和日志格式，不复用 HTTP 状态码。
- 公开响应体禁止原始输入、口令、连接串、SQL 和异常消息；诊断上下文只进入受控日志。

## 取舍与验收

该契约减少边界 `catch` 分支，同时保留领域异常的独立职责；它是 TypeApp 项目契约，不声称 PSR 定义了统一异常接口。验收覆盖公开异常响应、字段校验响应、未知异常脱敏和 CLI/HTTP 错误码一致性。
