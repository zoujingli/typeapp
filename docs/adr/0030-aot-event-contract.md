# AOT 事件契约与失败流程分离

状态：已决定，2026-11-15

## 背景

事件通知和异常传播承担不同职责。命令生命周期需要固定的 `ready/completed` 通知，业务事件需要当前执行作用域内的强类型同步分发；运行时扫描监听器或使用字符串事件总线会破坏 TypePHP 的静态装配和作用域检查。

## 决策

- 生命周期事件只使用 `LifecycleEvent::READY` 与 `LifecycleEvent::COMPLETED`，监听表由构建期登记，运行时拒绝未登记名称。
- 业务事件使用 `BusinessEvents` 和 `EventDispatcher`，事件对象及监听调用由构建期生成；分发保持同步、按登记顺序执行并检查所属执行作用域。
- 事务提交后通知继续通过 `Db::afterCommit` 等明确入口表达，不把提交、重试或持久投递隐含到普通事件分发。
- 监听器异常直接传播并触发命令/作用域清理；异常契约不通过事件重新发布，也不使用事件替代失败返回。
- 不引入运行时 PSR-14 扫描、容器发现或任意字符串事件注册；PSR 兼容只体现在公开接口签名和显式适配层。

## 取舍与验收

固定登记使二进制可脱离源码运行，代价是新增事件必须重新生成并编译。验收覆盖事件顺序、无监听、作用域隔离、监听器异常传播和生命周期未登记事件拒绝；异常验收独立执行。
