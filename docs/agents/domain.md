# 领域文档约定

当前采用单一语境：根术语表与统一架构决策目录。多 Composer 包不自动等于多个领域语境；只有词义、所有权或业务规则真正分化时再建立语境地图。

设计和探索前阅读术语表，以及涉及目标行为的架构决策。标题、假设、任务、测试和代码说明使用已确定的“开发主仓”“插件包”“分发子仓”“应用模板”“分发批次”“完整交付”等词汇。

术语表只写术语、简明定义和易混淆词，不写实现计划、文件布局、超时参数或任务状态。中文标题和“避免混用”表述适配项目语言偏好。

出现新词义时按 domain-modeling 及时澄清并记录。架构决策只记录难以逆转、存在真实替代方案且未来读者需要原因的选择；使用连续编号、短标题及一至三句背景、选择与原因，必要时增加状态。

已确定的架构变化同步术语、现行决策、实现说明及规划，说明实际影响。缺少不相关领域文档时正常继续，不先创建空文档。
