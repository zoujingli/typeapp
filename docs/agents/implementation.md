# 实施约定

采用 implement 的最小连贯变更原则，并遵守当前会话指定的技能。

1. 读取当前需求、实现规划、相关术语与架构决策；有明确 Issue 时读取其完整内容；检查工作区并保留无关修改。
2. 按[项目标准](../standards/project.md)确认命名、全量编译与效率边界，再按行为追踪入口、调用者、领域对象、外部效果、失败路径和现有测试；搜索同类实现，先确认可以复用的所有者。
3. 在进度说明中给出简明复用图：需要的能力、现有入口或模块、最小扩展及预计新增文件。涉及线程、协程、通信或 I/O 时，先读 [Swoole 复用标准](../standards/swoole-reuse.md)，列出生产调用者、固定上游机制、必须补的项目职责和待删除旧路径；原生补丁另核对缺口证据及撤除条件。当前没有功能源码时如实说明，不编造现有实现。
4. 实现一个任务的完整路径；优先复用现有模块，只有新的责任、真实变化点或重复代码需要时才增加抽象。
5. 在既定公共接口处验证外部行为，新增必要回归用例；任务跨数据库、网络或进程时使用相应真实依赖，不用内部 mock 证明协议正确。
6. 检查最终差异是否匹配需求与复用图，按[主分支开发与临时资源](../standards/project.md#主分支开发与临时资源)保全证据并回收本任务临时文件、进程和测试资源，记录实际验证、未验证限制及保留项。

## 开发顺序

先学习锁定版本的 TypePHP，再按其语法和语义完整实现项目，最后集中编译验收与调整。修改生产源码、生成器或示例前，阅读 [TypePHP 0.9 语法基线](../standards/typephp.md)；涉及新的语言特性时，先核对锁定版本的一手文档、实现及 PHPT，将规则与具体调用者对应后再编码。PSR 是公共接口约定，生产实现以锁定 TypePHP 为目标语言。

学习完成的标准是：相关入口、变量类型、对象表示、回调参数与外部扩展边界均有依据；实现完成的标准是：所有调用者、生成源码和独立消费示例遵守同一契约。保持明确的参数签名、稳定的局部变量类型和显式状态；TypePHP 的有意规则直接用于设计，不增加运行时猜测或裁参层来恢复 PHP 宽松行为。既有公共接口完整时可以并行实现消费者，缺少接口先补齐依赖。

实现统一到上述基线后，再核对差异、配置及必要检查，集中执行全量 AOT 和对应外部行为验收。PHP 语法或行为检查仅作辅助证据；分别记录“按 TypePHP 实现”“PHP 行为已验证”“原生验收已通过”。发现编译器缺陷时保留最小复现及版本依据，修改仍遵守语言规则。只有该任务的全部验收标准通过后才关闭 Issue，完整交付要求生产源码与依赖全量编译。

既定测试接口是“安装后的插件公共接口”和“编译产物的应用入口”。具体任务沿用这些接口不重复询问；只有需要新增或改变观察接口时才重新明确范围。

当前按学习、实现、验收的顺序推进；用户另行要求 TDD 时再采用一条失败测试到最小实现的循环。文档和低风险可逆配置变更只做适当的格式、引用与差异校验。

生产兼容必须由 TypePHP 编译和对应驱动实际运行证明。未完成、占位、源码解释回退、未知提交结果或未验证 ABI 均明确报告。

## 提交与前端处理

用户已授权：已要求的修改完成检查后直接创建 Git 提交，无须再次询问是否提交。远端同步沿用当前会话已明确的授权；这条提交约定不扩大实施范围，也不自动授权创建 PR、发布应用、部署或公开子仓。

1. **先检查再提交。** 核对工作区与最终差异，完成该功能适用的检查、测试和必要构建，再检查暂存区内容及空白错误。必需验证未通过时先解决问题，并如实报告尚未完成的检查。
2. **按功能组织提交。** 不同功能分别提交；同一功能的前后端修改、测试和文档组成连贯提交。共享准备改动在确实可独立验证时单独提交，避免为了文件类型或目录拆散一个功能。
3. **准确暂存。** 按功能选择文件或变更块，保留用户无关修改；提交前检查暂存区，提交后核对提交内容与剩余工作区状态。
4. **前缀与中文描述。** 提交信息使用 `前缀(可选范围): 中文描述`。常用前缀为 `feat`、`fix`、`docs`、`refactor`、`test`、`ci`、`build`、`perf`、`style`、`chore` 和 `revert`；描述写清实际变化，需要正文时同样使用中文。例如 `feat(orm): 支持 SQLite 文件数据库`、`fix(core): 修复请求退出时的资源清理`。
5. **前端变更同步纳入。** 涉及该功能的前端源码、样式、配置、锁文件，以及仓库约定应跟踪的产物，一并检查并提交。生成目录是否纳入版本控制以仓库现有约定为准。
6. **本地前端不自动更新。** 默认不发布应用、不替换或更新本地前端、不执行前端部署或自动重启本地服务。必要的前端检查和构建可以用于验证，运行它们不代表授权部署产物。
7. **报告实际结果。** 完成后说明各功能对应的提交、执行过的检查，以及尚未提交或未验证的相关内容；远端推送结果与本地提交结果分别说明。
