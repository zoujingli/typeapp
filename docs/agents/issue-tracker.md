# 需求跟踪

当前实现以源码及配套说明为准，已确定但未完成的目标维护在[实现规划](../guide/roadmap.md)。GitHub Issues 用于经授权的新需求协作，仓库文档和代码注释直接说明行为、约束与验收条件。

读取或操作 GitHub 时核对目标仓库 `zoujingli/typeapp`，获取完整正文、评论、标签和依赖；跨目录操作显式传入 `--repo`。写入动作沿用会话授权，多行正文通过 UTF-8 文件与 `--body-file` 提交，随后回读核对。

需求须描述问题、预期行为、范围及可观察的验收条件。任务只包含一条完整行为，依赖只表达真实前置条件；领取、分配、发布评论及关闭分别遵守授权。任务完成后同步当前文档与规划，局部通过不能代表框架完整交付。

临时调查、拆分草稿与执行日志放在任务专用工作目录，完成后回收。版本化文件保留最终规范、使用说明、可复用验证方法及当前规划；实现细节不依赖 Issue 编号、评论或旧运行快照才能理解。
