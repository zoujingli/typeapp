# 工具约定

## 已确定的入口

- 代码与历史使用 Git，操作前核对工作目录、远端、分支和工作区状态。
- 开发位置、并行作业预算及命令结束后的资源回收遵守[主分支开发与临时资源](../standards/project.md#主分支开发与临时资源)；独立消费验证的临时安装目录也在回收范围内。
- 项目 Issue、标签、依赖与 PR 使用 `gh`，目标仓库为 `zoujingli/typeapp`。
- 本地文件和文本优先用 `rg` 查找，读取相关范围；独立只读查询可以并行，依赖操作和修改按顺序执行。
- 文件编辑使用明确补丁。多行 GitHub 正文通过 UTF-8 文件和 `--body-file` 传递，不把不受信任文本插入 shell 命令。
- 写入文件的路径遵守[路径与环境可移植性](../standards/project.md#路径与环境可移植性)；项目相对路径与外部工具定位分别解析，不把本机绝对目录保存为其他环境的默认值。
- 说明写清用途、限制和操作结果；日志字段、错误码和命令参数保持稳定。

## 随实现建立的入口

Composer 管理本地插件与依赖锁定，TypePHP 负责编译。当前原生命令的实际安装、构建与验证入口见 [开发说明](../development/native-command.md)，脚本清单以根 Composer 配置为准。GitHub Actions 已定义该闭环验证，插件分发及其他框架能力仍由对应任务实现，不能把规划中的命令当作全部可用。

测试以任务涉及的最小有效检查开始；需要编译产物、真实 MySQL、PostgreSQL、SQLite 或 Redis 时按规格验证。普通语法检查、JSON 解析或文档检查不能替代框架集成测试。

## 外部操作

只读检查与用户明确要求的入仓操作按授权推进。涉及发布凭据、仓库可见性、删除数据、移动标签或改写历史时核对准确目标和现有授权；缺少必要权限先完成可审阅材料，再准确说明缺口。

跨仓 Actions 使用明确映射和受限凭据，普通 PR 不获得发布权限。验证只针对受控测试资源；不把主仓默认令牌当作全部子仓的写权限。
