# 数据库连接身份与会话隔离

Driver 提供不含密码的身份描述，包含驱动、端点、数据库、用户、凭据代次、TLS 验证信息、会话配置和 reader/writer 角色。SQLite 内存库每份驱动配置具有独立身份；文件库仍要求明确本地绝对路径。

MySQL、PG 驱动可配置受信任 CA，CA 哈希进入连接身份，文件变化必须重新声明连接。MySQL 检查协商结果确实使用 TLS；PG 使用 verify-full，未启用 TLS 时显式 disable。PG 可声明 schema 与数据库 role，所有标识符先检查再设置。reader 身份初始化数据库只读配置，Connection 进一步拒绝写入和会话修改入口；它是程序用途约束，不替代数据库最小权限账号。

查询结束关闭结果游标，租约归还先处理流和残留事务，再由 `Driver::reset(PDO): bool` 确认完整会话基线。PostgreSQL 使用官方 `DISCARD ALL`，清除会话变量、角色、临时对象、准备语句、通知和会话级咨询锁，再恢复配置的 role、schema、UTC、DateStyle 和读写用途；成功才将原物理连接放入有界空闲池。SQL 错误、未知提交、重置失败或已退役凭据代次的连接均关闭。

MySQL 的标准 PDO 接口没有完整会话重置能力；SQLite 的任意 PRAGMA、附加库和临时状态也未实现完整重置。这两个驱动当前归还即关闭物理连接，下次借用重新认证和初始化，不将它们描述为物理复用。SQLite 内存数据仅存在于持有的物理连接期间，归还后不承诺跨租约保存内存库。

`query`、`execute`、`raw`、`rawQuery` 以及生成查询遵守同一规则：SQL 的首关键词不能证明没有副作用，SELECT 内的存储函数及写入触发器同样可能改变会话。复用取决于完整重置结果；不能仅恢复几个已知变量就认定连接干净。`idle/created` 是池中资源数量，实际复用验收另检查服务端连接 ID。

池只在第一次借用时初始化，fork 前可创建尚未借用的配置/Database；已在其他进程创建的活动池不能继承使用。`ResourcePool::retire()` 拒绝新借用但允许当前租约完成。`DatabaseManager::rotate()` 要求凭据代次增加，为新借用使用新配置，旧租约仍携带自己的旧身份；最多两个未排空旧代，避免无限轮换积累连接。部署总预算需要计入新旧代并存。

PHP 三库验证覆盖临时状态、时区、PRAGMA、命名读写用途、代次隔离、旧池排空与实际 fork。MySQL/PG 使用真实临时数据库用户完成密码轮换，确认旧会话可以继续、旧密码拒绝新建、新代使用新密码；PG 补充 role/schema 基线恢复。

原生入口为 `docs/build-config/type-identities.json`，密码轮换验证器同样支持传入原生产物。`bf28c8b` 的 Linux x64 数据组已通过三库原生身份与主从用例；TLS 组另验证真实证书、连接成功及身份拒绝，macOS 也完成三后端 PHP/AOT TLS 回归，见[发布验收](../evidence/native-release-20260925.md)。这些结果不等于任意 SDK、数据库版本或部署组合均已通过。
