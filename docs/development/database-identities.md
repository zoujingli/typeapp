# 数据库连接身份与会话隔离

Driver 提供不含密码的身份描述，包含驱动、端点、数据库、用户、凭据代次、TLS 验证信息、会话配置和 reader/writer 角色。SQLite 内存库每份驱动配置具有独立身份；文件库仍要求明确本地绝对路径。

MySQL、PG 驱动可配置受信任 CA，CA 哈希进入连接身份，文件变化必须重新声明连接。MySQL 检查协商结果确实使用 TLS；PG 使用 verify-full，未启用 TLS 时显式 disable。PG 可声明 schema 与数据库 role，所有标识符先检查再设置。reader 身份初始化数据库只读配置，Connection 进一步拒绝写入和会话修改入口；它是程序用途约束，不替代数据库最小权限账号。

默认保证完整会话隔离：查询关闭结果游标，归还时处理事务并关闭物理 PDO 连接，下次借用重新认证和初始化。逻辑池槽位可以复用，统计中的 idle/created 是槽位数量；物理连接不会因未知会话状态跨请求复用。该保守策略有重新连接成本，经证明的驱动 reset 可以作为后续优化，不能牺牲身份隔离。普通 SQLite 内存数据仅存在于持有的物理连接期间，归还后不会承诺跨租约保存内存库。

池只在第一次借用时初始化，fork 前可创建尚未借用的配置/Database；已在其他进程创建的活动池不能继承使用。`ResourcePool::retire()` 拒绝新借用但允许当前租约完成。`DatabaseManager::rotate()` 要求凭据代次增加，为新借用使用新配置，旧租约仍携带自己的旧身份；最多两个未排空旧代，避免无限轮换积累连接。部署总预算需要计入新旧代并存。

PHP 三库验证覆盖临时状态、时区、PRAGMA、命名读写用途、代次隔离、旧池排空与实际 fork。MySQL/PG 使用真实临时数据库用户完成密码轮换，确认旧会话可以继续、旧密码拒绝新建、新代使用新密码；PG 补充 role/schema 基线恢复。

原生入口为 `docs/build-config/type-identities.json`，密码轮换验证器同样支持传入原生产物。TLS 已实现验证配置与失败关闭策略，证书联调和原生身份验收仍在待验收清单，不据此声明全部部署组合已通过。
