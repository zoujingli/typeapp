# 公开插件分发批次

计划记录源码 SHA、各包拆分提交和树、模式、版本、Git 版本和锁定工具链文件的 Git 对象。完整计划内容决定批次 ID。同一工具身份和输入产生同一 ID，工具身份变化会形成新批次；不能拿旧报告给不同源提交背书。

三个分发入口共用原生 CI 门禁：源码必须对应主仓 `main` 的固定 SHA，`native-command.yml` 在同一次执行轮次中整体成功，所有任务已完成且成功，并包含 `native-complete` 汇总。自动 push 与手动 `suite=all` 均可提供证据；`[skip ci]` 提交需手动运行完整验收。汇总仅在完整矩阵成功后通过，`isolated-build` 单项重跑、跳过或失败任务、其他仓库/分支/提交，以及不完整的任务列表均不构成分发资格。

每个矩阵任务只拿一个子仓的专用写入 deploy key。通过 GitHub API 核对准确仓库名、public 可见性和未归档状态；目标不符或无法确认时停止分发。Actions、PHP、Composer 和源提交固定，PR 没有分发入口。包中的允许内容为 composer.json、README、LICENSE、NOTICE、src/bin/stubs/resources；未映射依赖、认证文件及额外根内容均拒绝。

单组件入口 `tools/distribute-plugin.php` 与批次计划共用包检查：从指定提交核对 Composer 声明、普通文件类型、允许路径、第一方依赖及拆分树。每个组件必须包含 `README.md`、`LICENSE`、`NOTICE`；README 和 NOTICE 不能为空，LICENSE 的 Git 对象须与同一提交的主仓完整 Apache-2.0 许可文本一致。工作区补写文件不能修复固定提交的缺项；这些检查必须在向分发仓库写入前完成。

构建组件另精确允许`type-build/docs/operations.md`，因为`type package`必须随产物提供该手册；并未开放整个docs目录，其他内部说明仍由拒绝回归保护。

分支只允许快进，绝不 force；同名标签内容不同直接失败，相同标签重复执行不改动引用。两个执行者竞争创建同一标签，由 Git 原子引用更新裁决，失败方重新回读；若已是期望提交则视为完成。开发分支后续前进不影响旧标签批次幂等回读，过期分支批次则拒绝倒退。子仓自行修改会导致谱系偏离，需人工理解变更后在主仓处理，工具不替维护者覆盖。

多仓更新不是原子事务。每包生成成功或失败结果，最终汇总必须包含所有包，批次 ID、源码提交、拆分提交、仓库、包名、模式及版本均须与计划相同；成功报告还须对应计划的分支或标签引用。缺少或错配的报告不能计为完成，当前批次的失败报告保留原始诊断。部分失败时重跑同一输入，会按远端实际状态补齐；不回滚已成功的仓库、不移动旧标签。Actions 工件保留 90 天，长期发布记录应归档到项目制品存储。

模板分发与批次消费接收汇总报告时，必须从当前固定提交的映射和完整 Git 历史重新生成计划，核对报告协议、源码、模式、版本、批次 ID、完整组件集合及每项成功回执。仅设置 `complete: true` 不能通过；缺项、额外组件、失败状态或身份错配均在外部操作前拒绝。浅克隆不能用于此项复核，消费工作流使用完整历史；Git 工具版本变化使计划身份变化时也会拒绝旧报告。报告核对证明输入一致性，远端实际内容仍须由分发回读及独立安装验证。

模板发布将结果写入 `build/distribution/template.json`：`publish-status` 记录远端分支写入结果，`checkout-verified` 记录重新克隆后的提交与树验证。有效输入开始处理即更新当前报告；准备、发布或克隆失败写入 `status: failed`、阶段和原因，避免留下上一轮成功状态。克隆失败不会回滚已经写入的远端分支。模板独立消费同时复核该报告、完整组件批次和未改动的模板检出，具体入口见[模板部署验收](template-deployment.md)。

汇总成功后独立消费任务通过 HTTPS 从真实公开 Git 仓库安装所有包；每个 Composer source reference 必须等于批次拆分 SHA。开发分支提供 `dev-main → 1.0.x-dev` 标准 Composer 别名，跨包范围无需本地 path 配置才能满足。构建工具为 require-dev，生产包闭包整体编译；所有源路径来自消费者自己的安装目录。

## 凭据配置

`php tools/provision-distribution.php --create-public-targets` 创建映射中的公开仓库和独立写入密钥，并将仓库简介设置为对应 Composer 清单的 description。它保留已有凭据，不把已有私有仓库自动公开；重建由明确授权的初始化流程负责。写入 secrets 使用 stdin，私钥临时文件在提交后清理，不进仓库。外部网络失败可重跑；第一次在 GitHub 增加 key 后、保存 secret 前中断时，可能留下没有可用私钥的旧公钥记录，需按专用标题与创建记录清理。

公开组件通过 HTTPS 获取，Composer 消费不需要 SSH 密钥。每个分发仓库只配置专用写入 key；模板工作流使用 `tools/configure-distribution-writer.php` 加载模板写入 key，并在退出时用 `tools/cleanup-distribution-writer.php` 清理。凭据只用于发布写入，不传入公开组件的安装过程。

## 验证

`composer test:distribution-batch` 使用真实本地裸 Git 仓库和多进程，验证首次分发、重复执行、报告身份错配拒绝、部分失败补齐、不可移动标签、相同标签竞争、开发分支前进后旧标签重跑、过期批次、子仓偏离和私有内容隔离。每次在 `build/` 创建独立目录，成功或异常退出时等待本轮子进程并回收目录，清理不跟随符号链接。

远端验收由上述 Actions 的 plan/publish/collect/consume 任务完成。`tests/batch-consumer.php` 读取完整批次报告并安装全部公开插件，原生模式额外编译公共组合；完整业务另由集成验收覆盖，不能用这里的安装证据代替全部业务和故障验收。消费项目在安装前从同一固定提交逐字节提取示例入口与工具链文件，工作区修改不会混入该批次的构建输入。

PHPUnit 下游回归从真实本地裸 Git 仓库的发布回执生成报告，覆盖分支、标签、报告身份与内容错配、浅克隆拒绝，以及消费输入的工作区隔离。外部命令由拒绝哨兵截断，所有临时目录结束即回收；此回归不代替实际 GitHub 分发、Composer 安装或 AOT 验收。

### 组件与模板的本机候选

`composer test:distribution-candidate -- 当前完整SHA` 从该提交读取分发映射、拆分全部组件及公开应用模板，并从同一提交提取示例入口与工具链文件。组件范围随映射确定，候选准备不读取这两个文件的工作区修改。独立安装后核对组件字节，再执行全量生产编译与模板消费验收。候选目录创建后的准备、安装或验收失败均写入 `verification.json`，保留失败原因及已完成的组件快照供复核。

所有候选归档在导出前读取 Git 文件清单，仅接受普通文件；解包后逐项核对文件集合及 Git blob 字节身份，验证后才记录 SHA-256。`export-ignore` 删除文件或 `export-subst` 改写内容导致快照偏离时立即失败；组件、模板和完整应用均使用这项检查。

PHPUnit 的候选准备回归使用临时 Git 仓库，覆盖公开模板、未提交输入隔离、导出属性造成的快照偏离及准备失败报告；它在安装前结束，不作为独立安装或 AOT 通过的依据。包材料回归分别经过单组件命令和批次入口，验证材料缺失、不完整、未允许文件及未映射依赖的拒绝行为，全部使用本地资源并在结束时回收。

### IoT完整应用的本机候选

`composer test:distribution-candidate -- 当前完整SHA --iot` 从固定Git快照导出完整应用到新消费目录，按原始Composer锁安装，核对每个本地组件字节以及所有vendor软链接的相对目标均在快照内部。沿用原锁的`symlink=true`，不把`COMPOSER_MIRROR_PATH_REPOS`当作覆盖它的开关；此模式包含`type-mqtt`、全部业务与生产依赖，完整业务范围由源码快照和生产依赖锁共同确定。

准备匹配锁的`PHP_HOME`、`PHPX_HOME`、`PHPRC`和`TYPE_COMPOSER_PHAR`；`PATH`提供Web声明的Node.js与精确pnpm版本。`TYPE_MYSQL_TOOLS`、`TYPE_PGSQL_TOOLS`和`TYPE_REDIS_SERVER`分别指向本机原生工具；`TYPE_MQTT_CLIENT_ROOT`指向已安装锁定MQTT.js测试依赖的目录。路径均在执行时解析，工具来源和版本由各装置记录。所有数据库都由现有装置在新私有目录建立并关闭。

入口先执行Vben冻结锁安装、类型检查和生产构建，再单路完整AOT；顺序复用运行包搬迁及禁读源码检查、通用框架三库PHP/AOT对照、IoT三库授权/查询/恢复以及真实同步PostgreSQL上的MQTT接入、可靠上报、控制与结果查询。运行包通过现有`NativePackage`建立，业务不依赖源码或主仓vendor。完整输入、依赖锁、编译报告、产物摘要和场景日志留在`build/iot-candidate-*/verification.json`及同目录；失败原件保留，不能通过替换旧产物宣称成功。

支持专项使用独立数据库，因为设备转移装置保留的有效支持授权会改变它的初始授权数量。长时间验收应保持宿主唤醒；macOS可用`caffeinate -is`包裹上述命令，断言随命令结束释放，不修改系统电源设置。宿主休眠导致真实游标/授权期限流逝时，保留失败原件并在新场景重验，不能放宽业务有效期。

当前IoT内核禁源码装置仅在macOS执行，因此此入口明确限制为macOS本机局部候选。它不冻结最终交付，不替代Linux x64、完整协议条款、真实页面走查、容量/长期运行以及各前置任务的验收；也不推送、触发Actions、部署或更新本地前端。每次源码变更都生成新的固定快照与候选，不沿用不同源码的成功结论。
