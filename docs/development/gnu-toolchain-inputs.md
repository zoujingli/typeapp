# GNU工具链输入与私有sysroot

Linux构建身份由`BuildEnvironment`维护。GCC/G++入口、实际驱动、内部编译程序及加载库分别记录，不能只凭包装脚本或版本文本代替实际工具字节。

## 默认目录来自实际编译器

在与构建相同的受限环境中，分别以C和C++预处理空输入，读取GCC的实际驱动与头文件搜索顺序；不再固定扫描宿主`/usr/include`。实际sysroot以及默认启动对象、GCC运行支持和specs等解析到的文件也进入记录。未解析到的可选支持文件保持缺失，不猜测替代路径。

输入目录内容继续通过原有`BuildIdentity`进行摘要和符号链接越界检查。GCC诊断中的绝对路径可包含`../`，工具先拒绝控制字符再解析真实路径；这不放宽用户构建JSON的路径规则。保留实际搜索顺序，目录或文件集合的变化同样影响身份。

诊断格式或驱动无法确认时明确失败，不退回猜测目录。探针只使用固定shell重定向，编译器路径和语言通过独立、被引用的参数传入，不插值执行任意命令；业务变量与预加载配置不进入子进程。

这不是扫描整个sysroot，也不声称能发现不透明包装器读取的任意外部配置。自定义工具应保持构建环境显式；macOS/Windows仍走各自既有的平台指纹实现。

## 回归入口

仅在本轮专用、当前用户持有的可写SDK副本中执行，不用于生产或多人共用SDK：

```sh
composer test:gnu-toolchain -- /私有sysroot
composer test:gnu-toolchain -- /私有sysroot --native
```

测试只创建自己唯一命名的头文件并在finally中回收，不修改既有SDK头文件。基础检查验证实际驱动/标准头文件被记录、内容变更（保留mtime）改变身份、未变化时身份稳定，以及越界链接继续拒绝。

原生模式通过正式CLI构建及运行小型应用，验证四个连续状态：

| SDK探针内容 | 期望行为 |
| --- | --- |
| 首次内容1 | 编译，缓存未命中 |
| 同样内容1 | 命中同一产物 |
| 内容改为2且保留mtime | 身份变化，重新编译 |
| 恢复内容1 | 复用原身份及相同二进制 |

该回归针对GNU输入发现与真实原生缓存；不以它替代整应用、三库或全部平台验收。原生Linux虚拟机和标准Linux工具布局的实际增量证据另行记录，容器补充检查与不经Docker的主机编译不混称。
