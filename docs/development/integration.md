# 十四插件的完整业务集成

集成代码按锁定 TypePHP 语法实现，使用同一套用户、文章、标签模型，独立安装十四个库与驱动。构建与测试工具作为开发依赖；十二个生产插件及 PSR、Cron 等传递依赖完整进入 AOT。

## 业务与公开接口

`Scenario` 依次执行输入校验、三库模型事务与关系写入、Outbox 发布、队列消费、模型版本更新、缓存失效、同消息重放幂等、Cron 到受保护队列投递、审查状态更新，以及 PSR 缓存和结构化日志。HTTP 入口用认证与显式授权读取同一份文章 DTO，并验证未认证请求和有限停止。

复用 `examples/orm-suite` 的模型与迁移、既有 Outbox 发布适配器和调度投递任务。没有另建隐藏 ORM、内存队列或假驱动。`tests/integration-consumer.php` 检查安装来源及生产编译清单，使用复制安装，所有生产源都来自该消费者自己的目录；原生模式实际执行 ELF。

`Measurements` 先预热 50 次，再顺序执行 500 次带作者和标签的文章查询。它每 50 次保存 RSS、Zend 内存和连接池状态，并记录延迟分位数、错误数、消息年龄、构建耗时、ELF 体积及平台信息。此输入用于重复观察回归；长时间负载、故障和恢复由对应任务的独立场景补充。

## 重复执行与最终门禁

远端模式 `tests/integration-consumer.php <驱动> --remote --native` 要求先取得成功分发批次，所有插件必须安装批次记录中的准确提交。当前三库证据使用本地复制包；真实公开分发消费、最终 Linux x64 CI、全部故障演练及无源码部署仍待合并验收。未完成项见[实现规划](../guide/roadmap.md)。

## 无源码完整业务复验

`--native --isolated` 使用消费者自己的 ELF 和封装清单创建运行目录，只包含原生库、受控 ini、运行资源及应用二进制。控制器仍在外部测试进程运行；应用的 scenario 和 HTTP 进程在 chroot 内执行，不能加载消费者 vendor、PHP CLI 或业务 PHP 文件。程序运行前遍历隔离目录确认不存在 PHP 源文件，临时数据库与日志使用隔离内 `/tmp`，网络数据库和 Redis 仍是明确的测试依赖。

## 同一 ELF 的测量与隔离证据分开记录

隔离模式现在先使用同一份已编译 ELF，在具备真实 `/proc` 的原生环境执行完整业务，严格要求十个 RSS 窗口及 CPU、系统内存信息可读取；随后再次执行 chroot 无源码业务与 HTTP。两轮使用独立测试数据库和 Redis 业务命名空间，驱动及二进制不变。非隔离原生入口同样选择已准备的 embed ini，不能遗漏其信号或动态扩展配置。

最终报告保留隔离部署自身的 `measurements`（不可读取的项仍为 null），另以 `performance-baseline` 保存实际原生测量的环境、延迟、RSS、池与消息指标及相同 ELF 的 SHA-256。该基线明确标记 `deployment=development-runtime`，不冒充 chroot 内测量，也不把短时间单连接采样当作压力或长期泄漏证明。
