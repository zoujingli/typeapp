# Model 自动连接与主从路由

本文记录已确定的接口约定与待实施范围。当前 `ModelCompiler` 仍生成需要 `Connection` 的查询入口，模型保存也需要显式连接；下文去掉连接参数的模型 API、静态 `search()`、自动租户隔离、`master()` 和 `Db` 事务入口是实施目标，尚不能作为当前可运行示例。自动连接、自动租户隔离、静态筛选助手和物理连接复用属于同一批完整交付。

## 业务接口

业务 Service 围绕具体 Model 表达查询、赋值、持久化和事务意图，框架负责选择数据源、从池中借用连接并按执行作用域释放。具有指定租户字段的模型从当前可信执行上下文自动取得租户归属，业务不逐次补租户条件。

目标调用形式如下，`CustomerMember` 属于已规划的身份/租户模型：

```php
// 入口已验证并建立租户上下文；普通查询读从库，未配置从库时读主库。
$members = CustomerMember::query()->get();

// 授权检查、写后确认等明确需要主库的读取。
$member = CustomerMember::query()->master()->findOrFail($memberId);
$member->enabled = false;
$member->save();
```

`master()` 是当前查询的路由意图，返回新的查询对象，不修改其他查询的默认策略；它表示使用主库，不隐含行锁、事务隔离升级或跨请求的一致性保证。`save/delete/restore/forceDelete`、原子增减及关联写入自动使用主库；从库读出的模型保存时也必须转到同一逻辑数据源的主库，并保留版本冲突检查。

实体 CRUD 不要求控制器或 Service 接收、传递和关闭 `Connection`。迁移、驱动验收及明确的基础设施操作仍可以使用显式连接，普通业务不依赖该入口。每个 Model 声明稳定的逻辑数据源，默认使用应用默认数据源；数据源配置在应用启动装配，查询输入不能任意决定数据库地址或凭据。

## 静态筛选助手

生成模型的查询入口为 `query(string $alias = ''): ModelQuery`，新增 `search(array $input = [], string $alias = ''): QueryHelper`，内部只调用 `\_query(self::query($alias), $input)`。模型的查询和保存入口不保留 `Connection` 参数，显式连接仍属于底层接口。

```php
$members = CustomerMember::search(['enabled' => true, 'keyword' => '甲'])
    ->equal('enabled')
    ->like(['keyword' => 'name'])
    ->query()
    ->master()
    ->get();
```

三种入口具有不同职责：`Model::query()` 返回模型查询，`Model::search()` 创建不可变筛选助手，`ModelQuery::search()` 执行显式搜索器组合。`_query()` 的输入、返回类型和字段白名单语义不变；`QueryHelper::query()` 仍声明 `Query|ModelQuery`，模型静态入口创建的助手实际保留 `ModelQuery`。PHP 和 AOT 都必须验证上述连续调用。

助手不读取全局 Request，不将输入键自动解释为筛选字段，也不决定业务权限。模型租户隔离由底层 ModelQuery 根据上下文统一执行，`search()` 和直接 `query()` 遵守相同边界。缺失输入和空字符串跳过、`0/false` 有效、`null` 表达空值的既有筛选规则保持不变。助手的 `paginatePage()` 会执行查询，模型入口的分页同样自动遵守租户范围；其他业务筛选仍由调用者显式声明。直接包装底层表 Query 的助手不具有模型租户隔离能力。

`master()` 保持为模型查询的方法，不在助手中增加同名转发。模型自行声明 `search()` 或其大小写变体时，沿用生成成员冲突检查，在编译期明确拒绝。关系工厂、开发加载和 AOT 使用同一生成契约。

## 自动租户隔离

默认在模型列映射中识别 `tenant_id`；特殊模型通过 `Table` 声明实际租户字段，例如客户角色的 `scope_id`。字段映射在编译期确定，运行时从当前 Swoole 执行作用域读取租户身份；不扫描数据库来猜测归属，不以字段是否允许批量赋值决定隔离是否生效。普通业务不提供 `forTenant()`，连接池和物理 PDO 均不保存业务租户身份。

具有租户字段的模型在缺少可信租户上下文时明确报错，不执行无范围查询；没有租户字段的全局模型不受此限制。新增自动填充当前租户，显式输入与上下文冲突时拒绝。普通赋值、批量赋值和保存不能改变已有记录的租户归属；跨租户转移使用专门业务流程，保留授权、审计和原有一致性规则。

自动隔离覆盖查询、分页、聚合、关联和持久化。租户条件与业务条件分别组合，业务中的 `OR` 不能扩大租户范围；关联经过全局模型后，再访问租户实体仍须保持原范围。部分字段查询、水合模型和保存过程必须保留归属信息，不能只在列表查询中追加一次普通 `where`。

应用入口负责验证身份和目标租户访问资格，再将结果绑定到执行上下文；请求头、筛选输入和队列消息中的租户值不直接成为授权依据。全局账号、会话和租户目录与租户内实体分别建模，账号身份不能代替当前租户，租户隔离也不能代替业务权限检查。

跨租户例外集中在已授权的系统入口，普通 Model 不提供关闭租户隔离的方法。平台管理单个租户时，入口验证平台权限并绑定目标租户；登录后列出本人可用租户、平台汇总和后台领取任务使用职责明确的受控查询。不能用普通 Service 的表查询绕过模型边界，也不因管理员身份自动取消所有过滤。

水合模型保留原始租户，部分投影也保留内部归属信息；持久化条件包含主键和原始租户，并验证当前上下文仍匹配。租户上下文改变后，已有查询或模型不能静默转向其他租户；跨执行作用域只传受控值，重新查询目标对象。

受管子任务继承已验证租户标识的值快照，使用自己的作用域、会话和租约，不继承父事务。持久后台任务从服务端记录恢复来源，按业务要求重验会话和当前权限后建立租户上下文；消息携带的普通关联数据不能自行建立可信身份。任务退出恢复或清除绑定，已受理操作的结果对账仍按原业务规则继续。

当前 HTTP 作用域在认证前创建，认证结果仍主要保存在请求属性；尚未形成模型自动隔离所需的可信上下文链路。实施必须同时衔接认证入口、受管子任务和后台任务的上下文生命周期，并验证不同请求、消息和任务之间不会串用租户信息。

## 路由与一致性

| 操作或条件 | 连接选择 | 语义 |
| --- | --- | --- |
| 事务外普通查询 | 已配置的从库 | 接受复制延迟；写后也不自动粘主 |
| `master()` 查询 | 主库 | 当前查询及其关联读取沿用主库 |
| 创建、更新、删除、恢复、关联写入、原子增减 | 主库 | 不因模型来自从库而改变写入目标 |
| 事务中的查询与写入 | 该事务的同一主库连接 | 关联查询、聚合和嵌套事务共同遵守 |
| 行锁查询 | 主库 | 仍需有效事务及所选数据库真实锁语义 |
| 登录、会话有效性/撤销、权限与租户授权检查 | 显式 `master()` | 不依赖可能延迟的从库作授权判断 |
| 未配置从库 | 主库 | 单库配置，不属于故障回退 |
| 已配置从库不可用 | 明确失败 | 不转投主库，不隐式重试 |

写后需要立即确认结果时显式使用 `master()`，或者在同一事务内完成读写。一次主库查询不改变后续独立查询的路由。失败响应和日志需能区分从库连接失败、池等待超时、取消与事务结果未知，同时不暴露连接凭据。

主从选路在实际执行操作时完成。查询构造后再调用 `master()`、添加行锁或进入事务，都必须得到正确连接；不能在创建 `query()` 时提前借用从库。关系子查询与主查询使用同一执行连接，预加载及关联聚合继承本次查询的路由；分页的计数和数据查询保持同一路由，但事务外多条语句不承诺同一数据库快照。

每个逻辑数据源先配置一个主库端点和可选的一个只读端点；只读端点可以是数据库代理，不在 ORM 中增加复制管理或多副本选举。主从必须对应相同逻辑数据和驱动方言，SQLite 按单库使用。现有 `database.budget.replicas` 表示应用部署副本数量，不能复用为数据库从库配置。

## 协程上下文与事务

应用入口显式装配数据库配置和 `DatabaseManager`；请求、消息、队列、定时任务和 CLI 在各自既有执行边界绑定 ORM 使用的作用域。绑定直接使用 Swoole 当前协程上下文，不引入通用 DI 或新的调度器；没有有效作用域时明确失败，不临时创建无法回收的全局连接。

同一作用域按逻辑数据源复用受管会话，主从连接按需要分别借用。作用域结束时解除绑定并回收租约；错误、取消、Deadline 与中断走相同收尾规则，底层操作尚未结束时不能把连接重新发给其他协程。

子协程拥有自己的执行作用域、会话与租约，只继承允许的标识、取消、Deadline 和预算，不继承父连接或事务。进程/线程只能在各自执行环境内建立池；不能跨进程、线程或协程传递连接、活动事务及绑定连接的查询。需要传递业务信息时传值，并在新的作用域重新查询。

业务显式开启事务，但事务体不要求传入物理连接。事务上下文按数据源固定主库，嵌套事务继续使用现有保存点；回滚的模型失效、`afterCommit`、异常和未知提交规则继续生效。提交结果未知时明确对账，不自动重试写入。事务作用域内访问另一逻辑数据源的 Model 或 Db 操作直接拒绝，不能悄悄另开连接或独立提交；跨库工作放到事务外或通过 Outbox 协调。

手写业务事务采用 `Type\Orm\Db::transaction(Closure $operation, string $database = 'default'): mixed`，回调固定为 `Closure(): mixed`；提交后操作采用 `Db::afterCommit(Closure $operation, string $database = 'default'): void`，回调固定为 `Closure(): void`。`Db` 复用当前作用域的读写会话和现有事务实现，不持有全局活动连接。`#[Transactional]` 默认选择 default 数据源，指定数据源使用 `#[Transactional(database: 'archive')]`；模型声明使用 `Table` 的 `database` 参数，默认为 default。事务声明不再以业务方法中的 Connection 形参名选择连接。

TypePHP 的生成查询、关系工厂和事务声明入口必须一起修改。`#[Transactional]` 的生成调用不能继续强制业务方法声明 `Connection` 形参；直接调用未经生成包装的原方法仍不会自动开启事务。PHP 与 AOT 编译使用同一份生成结果。

## 连接池与物理会话复用

当前 `DatabaseManager → Database → ResourcePool → PdoSession` 已提供容量、等待、租约、凭据轮换和执行者校验。`PdoSession::reset()` 归还时关闭物理 PDO，空闲槽位复用不等于物理连接复用；标准应用目前还将空闲保留数设为零。

目标是在既有池中复用经过验证的干净 PDO 会话，避免普通模型操作反复认证建连。池容量、空闲上限和等待期限保持有界；归还必须关闭结果游标、处理未结束事务、清除本次作用域引用并恢复驱动声明的会话基线。会话修改、不可确认的状态、失效连接、重置失败和旧凭据代次均不能作为正常空闲连接再次借出，必须隔离并关闭。

原生 SQL 能力保留，但不要求任意原生语句执行后仍复用同一物理连接。无法证明没有会话副作用的字符串 SQL 入口应退役会话；该边界须贯穿 `query/execute/raw/rawQuery`，不能仅判断 SQL 的首个关键词，存储函数、触发器和命名锁等副作用同样需要验证。正常 CRUD 的物理连接复用与污染操作的连接隔离分别验收。

Swoole 官方连接池类的存在不代表 PDO 会话已清理，也不代表断连后的操作可以安全重放。复用官方能力时仍须保留当前事务结果、取消、资源预算和真实收尾规则，不叠加两个池，不引入透明写入重试；物理会话的可复用结论以所选驱动的实际结果为准。

MySQL 的时区与严格模式、PostgreSQL 的 role/schema/DateStyle、SQLite 的 PRAGMA 和临时对象等均需要真实驱动验证。不能只删掉关闭 PDO 的语句就宣布已实现安全连接池，也不能把“使用了 Swoole”当作会话已自动清理的证据。PDO 继续承担数据库协议，Swoole 负责执行、协程等待和资源边界。

## 实施与验收

| 范围 | 当前可复用内容 | 交付验证 |
| --- | --- | --- |
| 自动连接 | `DatabaseManager`、`ExecutionScope`、`ReadWriteSession` | 无参 Model CRUD、无上下文明确失败、借用次数有界、异常退出完整回收 |
| 自动租户隔离 | 模型字段映射、认证入口、作用域与受管任务 | 查询与写入自动限定归属，OR、关系、分页、部分字段和上下文切换不会越界 |
| 主从路由 | writer/reader 身份、事务固定连接 | 默认读从写主、`master()` 局部有效、取消自动粘主、锁查询主读、从库故障不转主 |
| 执行期选路 | 不可变查询与关系工厂 | 构造后再选主/进入事务、原子增减、预加载、聚合及分页均按实际操作选路 |
| 物理连接复用 | 现有有界池、PDO 会话及退役机制 | 同身份干净会话实际复用，污染/故障会话隔离，等待和关闭过程中不提前返还额度 |
| 身份/租户 | 领域 Model、当前 Service 与 HTTP 行为 | 模型、服务、迁移/夹具、回归测试和文档完整闭环，授权显式主读，业务版本语义保持一致 |
| 编译与分发 | 现有 Model/Operation 编译器及独立消费者 | SQLite、MySQL、PostgreSQL 的 PHP、独立 Composer、AOT 和移除业务源码后的原生运行 |

先完成自动连接、静态筛选助手和路由的完整调用路径，再将身份/租户切片接入无连接参数的 Model，物理池复用同步按驱动真实语义收口。调整全部受影响的模型和事务调用点、示例及模板，验证相关操作仍使用同一事务连接；其他业务从表查询改为 Model 的迁移继续按领域推进，不在本批批量展开。

专项覆盖同一工作进程内连续请求的状态隔离、子协程独立连接、事务中的并行任务边界、父取消与 Deadline 传播、真实收尾前连接占用、租户过滤与 OR 条件组合，以及失败认证不意外推进资料版本。文档与验收报告分开记录 API 已实现、PHP 已通过、AOT 已通过和完整平台验收；macOS ARM64、Linux ARM64、Windows x64 使用同一提交分别记录 Swoole、TypePHP、PDO 驱动与产物身份。
