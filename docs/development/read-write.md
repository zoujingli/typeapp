# 显式主从读取与执行内粘滞

`ReadWriteSession` 每次执行创建一份，绑定 ExecutionScope 与 DatabaseManager 中明确的 primary/replica 名称；要求同驱动的 writer/reader 身份。

`read()` 默认选择副本；`read(true)` 显式走主库。`write()` 和 `transaction()` 将当前执行标记为主库粘滞，之后 read 也走同一个主连接。事务回调中调用 read 不另借连接。每个新请求重新创建会话，不继承旧请求的粘滞；副本故障不自动切换重做任何写入。

提交结果 UNKNOWN 时保留未知事实并拒绝普通 read/write，包括主库粘滞读取。业务可显式调用 `reconcile()` 建立新主连接，按稳定操作 ID 对账；读取结果不能自动把上次事务判为已提交。完成对账后在新的业务执行中继续处理，不默认重跑未知事务体。

PHP 验证使用三种真实数据库的两个独立实例/库进行受控复制延迟：先保持副本落后，验证默认读取、强一致读、事务固定与提交后粘滞，再显式复制测试数据，确认新请求可从副本读到追平结果。该测试不冒充数据库原生复制配置，也不将 SQLite 文件快照视为多机共享数据库。

真实 MySQL 的 COMMIT 确认丢失故障同样经过 ReadWriteSession，验证 UNKNOWN 没有被主库粘滞掩盖。原生入口和相同故障验证已接入 CI，集中通过后才关闭任务。
