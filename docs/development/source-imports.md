# 第三方源码与资源适配

生产包可以声明自己的编译协议；没有声明的第三方包，由应用 imports 指定精确版本、源码与资源映射。

## 行为

- 构建工具使用 Composer 的 ClassLoader，但只注册 type-build 自身依赖闭包的类与函数文件。应用的自动加载初始化不会因启动构建器而执行。
- TypePHP 通过同一受限加载器的命令桥接启动；应用源码由编译器解析和转换，不通过 PHP 自动加载补齐缺失声明。
- 包自带的协议声明优先；应用适配只补充没有声明的包，并且必须匹配已安装版本。
- 显式收集 PHP、C/C++ 和 stub 文件，检查 PSR-4、PSR-0、classmap、files 的生产入口是否被覆盖。
- 排除项必须写明原因，排除后仍不得遗漏生产自动加载源码。复杂或不能解释的路径规则明确失败。
- 运行资源使用相对目标与内容校验，复制到按内容分代的目录；旧产物的资源不会被失败的新构建覆盖。
- 报告记录来源、自动加载入口、排除原因、生产源码和资源哈希。不把遍历整个 vendor 当作编译覆盖证明。

autoload.files 中只有声明的函数可以编译。顶层执行性初始化需要改为应用明确调用的可编译入口；当前不会自动重写它，也不会在构建期先执行它。

## 版本限定的源码适配

已有第三方库须按锁定 TypePHP 的语法规则调整时，可以在该包的精确版本 imports 声明 `rewrites`。每项包含 `source`、原始 `sha256`、中文 `reason`，以及 `replacements` 的 `from/to/count`。框架自己的源码直接按语言规则编写；这个入口用于审阅后的第三方版本适配。

`SourceSet` 先验证原始生产自动加载源码全部被覆盖，适配只能指向已纳入编译且不重复的 PHP 文件。`SourceRewriter` 校验原始哈希与每次匹配次数，在应用 build 目录生成完整副本并解析语法。替换必须保持行数；当前拒绝含 `__FILE__`、`__DIR__` 的适配文件，避免悄悄改变位置语义。已有生成文件被改动时也明确失败。

原始文件、生成副本、替换声明共同影响构建身份；编译输入使用生成副本，产物清单保留来源、前后哈希及中文原因。此机制没有跳过原库的其余生产文件，也没有在产物中保留源码解释路径。

当前 `type-scheduler` 对 Cron 3.6.0 的适配覆盖八个文件：`AbstractField` 分开字符串输入与整数候选值，`CronExpression` 分开表达式文本与表达式对象，并为日期引用使用 `std::any()` 与 `std::ref()`；接口及字段实现的日期引用声明使用等价的 `DateTime|DateTimeImmutable` 联合类型。固定局部存储和引用边界遵守当前锁定 TypePHP 0.9.3 的规则，所有原文件继续以精确摘要及替换次数校验，完整实现参与编译。对应声明保存在该插件 Composer 元数据中，独立消费者安装后得到相同规则。`composer test:source-rewrites` 比较原库与适配副本的字段校验、可变/不可变日期的前后向计算，并核对覆盖、原文不变、行号及不匹配输入拒绝；原生业务结果另由调度验收证明。

## 验证

在已有 Linux SDK 的环境执行 `composer test:imports`。独立消费应用安装真实 psr/log，以及覆盖 classmap、函数文件、原生 stub 和资源的测试库，编译后验证组合输出。

负向用例覆盖版本不匹配、生产入口遗漏、未知协议、资源路径越界和顶层初始化代码。最后一个用例设置哨兵文件，证明构建失败时没有执行应用自动加载文件，也没有替换已有成功产物。

本能力不意味着任意 PHP 包都自动兼容 TypePHP；源码本身仍必须通过实际编译和行为测试。
