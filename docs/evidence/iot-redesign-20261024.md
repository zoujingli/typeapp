## 现场已通过

- 保留现有两端账号、1 个租户、2 项产品分类、3 台设备及历史数据。三个设备转换为原始通信身份，旧产品、模型和原设备数据保存在升级账本，普通角色没有自动增权。
- 副本、本机代理入口、公网 HTTPS 和宝塔重启后分别完成 55 项真实 API 检查：两端登录、查询、退出、旧令牌拒绝、跨身份域令牌拒绝、控制端租户头拒绝、注册与管理写入返回 `403 demo_readonly`。旧数据处理、历史导出和业务指令入口返回 404。
- 安装后的 76 个前端文件逐项匹配候选清单。真实浏览器检查两端登录及退出、独立菜单、控制端租户及注册授权/接入应用页面、客户设备列表与升级来源详情、客户端应用页面；写操作按钮禁用，标题保留“物联开源分享”。浏览器自动请求的 `/favicon.ico` 返回 404，未计作业务错误，也未在现场增补候选之外的文件。
- 升级后至浏览器验收结束，81 张非会话/审计表与 3 个业务文件的摘要保持不变；认证会话和安全审计单独允许变化。前后账号哈希与身份字段保持一致。
- 宝塔停止、启动及单进程状态通过；业务任务 30/31/32 持续暂停，两次观察间隔超过 125 秒，原任务文件和日志无变化。每日备份、日志轮转和开机启动保留；官网 HTTPS 仍返回 200。

本轮不接入真实设备，不创建虚构在线、遥测或告警记录，不在只读站点生成新的注册资格或应用密钥。SQLite Demo 的范围是管理浏览与权限边界；现场数据没有被重装或重置。

11 个成功静态候选均已下载，附件 SHA-256 与 GitHub Artifact 身份一致，并通过正式 `Candidate::verify()`。本地将原始 ZIP 中的每个文件与解包副本逐项比对后，回收重复解包文件 1,416,595,840 字节；原始附件、下载回执和完整验证报告保留，可按回执恢复原目录。Windows PostgreSQL 的失败与复验材料单独保留，不算入这 11 个成功候选。

副本第一次停止检查误将 `runuser` 包装进程的信号退出当作应用退出；改为直接以应用用户启动同一程序后，正常退出码为 0。首次切换的即时进程检查早于旧进程退出，流量保持维护；加入有界等待、确认旧进程消失后继续，未在旧进程运行时升级数据库。这两项操作脚本问题及原始日志保留，没有修改生产程序。

回退必须停止应用与写入角色，恢复同一停服备份的配置、数据库、页面、业务文件及前端安装记录，再切换对应旧程序。不能只把旧程序连接到已经升级的数据。恢复后仍保持 `APP_ENV=demo`，验证通过后开放流量。

完整架构交付继续按 [#48](https://github.com/zoujingli/typeapp/issues/48) 及其任务验收，不因 Demo 更新成功而关闭尚未通过的矩阵任务。原始通信、高可用故障域、全部协议与性能结论按各自证据判定。
