# 首次 RC 自动发布验收

本记录区分发布前的四平台预检与版本 tag 的正式发布，两个阶段保留各自的源码身份。首次 `v1.0.0-rc.1` 的不可变 tag 指向 `9c8febf11b9997f3a76779825b3c7b2fb2fbbfb2`；[版本工作流](https://github.com/zoujingli/typeapp/actions/runs/36224276504)在 Windows 最终候选部署验收失败，没有进入子仓分发或公开 Release。修复使用后续提交和新的候选版本，保留原标签及失败证据。

## 发布前检查

源码 `48fc8df7997e85f029e351860da9537ee64f3d25` 的四平台完整矩阵通过。这一阶段没有生成公开 RC 附件，结果不能替代最终 tag 的验收。

随后提交两项发布工具修正：候选草稿预检取得读取草稿所需的仓库写权限；组件 RC 安装说明显式设置根项目 `minimum-stability RC` 和 `prefer-stable`，允许解析候选传递依赖。PHP 语法、格式、工作流语法和发布契约检查通过，定向契约套件为 86 个测试、1906 个断言。独立 Composer 离线夹具确认默认稳定性拒绝 RC 传递依赖，设置 RC 后两个候选包均按指定版本安装。

主仓与 16 个子仓在打 tag 前没有同名版本；子仓 Packagist push webhook 均启用，最近可观察响应均为 HTTP 202。正式发布仍须核对实际索引版本，不能用 webhook 配置代替消费结果。

## 执行与交付边界

推送最终 `main` 后创建并推送 `v1.0.0-rc.1`。同一提交额外触发的三项主分支构建已取消，以版本工作流执行完整四平台矩阵；取消的任务不计为通过。版本检查与共享前端构建已通过，后续阶段仍以真实运行结果为准。

Windows 候选 `prepare` 已完成打包、解包与完整性检查，随后 SQLite 验收约 0.2 秒退出。测试入口将 Windows `realpath()` 的反斜杠路径与包含正斜杠的构建目录前缀直接比较，错误拒绝了合法候选目录；定向回归在原比较逻辑下失败。修复统一 Windows 盘符与 UNC 路径分隔符，同时保留目录边界及 Unix 文件名语义，9 个路径用例通过。原日志上传范围遗漏候选内层错误，现已补入四平台失败证据；真实 Windows 补验仍按新的运行身份记录。

修复提交为 `2caa97cb78795bbc5ad333646c68e3b494d69c87`，本机完整单元套件通过 140 个测试、3160 个断言，格式、基础、文档和工作流检查通过。短暂启动的 Windows 手动候选诊断没有完成验收，随后取消；`rc.1` 中未完成的 macOS 分组也在保留运行状态后取消，不计为通过。新不可变标签 `v1.0.0-rc.2` 指向修复提交，由[新版本工作流](https://github.com/zoujingli/typeapp/actions/runs/36228227822)重新执行完整四平台及最终归档验收，不复用 `rc.1` 的候选文件或拼接原运行结果。

`rc.2` 的 Linux x64 与 ARM64 完整矩阵通过，macOS 已完成两个分组。对其 macOS 候选补充浏览器验收时，发现静态资源 `HEAD` 返回 `Content-Length: 0`，对应 `GET` 的脚本实际为 91 字节。页面响应提前换成空流，发送层按流大小生成长度，造成两者不一致；原候选验收只检查空正文，没有检查长度。为阻止不合格候选公开，取消其余运行。17 个仓库均无该版本 Release，16 个子仓均无该版本 tag；取消项和因取消而失败的聚合门禁不计为通过。

修复提交 `09cb1ec746ba88eb3e139cf332cefa1b644567f5` 保留文件流，由既有发送层统一省略 `HEAD` 正文并关闭流；新增首页和脚本的真实 HTTP 长度、类型及缓存标识校验。原逻辑的定向回归失败，修复后通过；完整单元为 140 个测试、3161 个断言。本机全量 AOT 编译 275 个单元，程序 SHA-256 为 `89408e2e0a4b8c0e6d0f7a889529af114bbf6edb6882d33f5cb3c86232774c7d`，其搬迁包通过隔离 SQLite 发布验收，包含真实 `HEAD` 长度及完整部署审计；本机产物不是公开 RC 附件。新标签 `v1.0.0-rc.3` 指向该修复提交，后续四平台产物重新编译并独立验收，不能替换 `rc.2` 原件。

`rc.2` 的 macOS 候选浏览器补验另有明确边界：原归档来自 macOS 15，本机为 macOS 27，`verify-runtime` 的系统 dyld 缓存审计因摘要不同失败。普通入口的运行库校验通过，隔离 SQLite 中的安装、双端登录、站点设置保存回读、角色增改查及 API 删除回读通过，83 个安装文件摘要一致，服务正常停止；这些功能结果不能替代完整部署审计，也不构成 macOS 27 的完整支持声明。最初补验脚本使用了沙箱不可读的工作目录，修正为允许的独立运行目录后才取得上述真实结果，原错误日志单独保留。

## RC3 原候选补验

`v1.0.0-rc.3` 的[正式工作流](https://github.com/zoujingli/typeapp/actions/runs/36230932433)固定源码 `09cb1ec746ba88eb3e139cf332cefa1b644567f5`。共享前端为 83 个文件，清单 SHA-256 为 `8cf440def909935206893729e6fcbee2317ef617aeee7959344c165f338d09f8`。

本轮 Linux x64 与 ARM64 完整矩阵通过；Windows 的最终 ZIP 在 PostgreSQL 空库 `app:install` 中断，外层日志仅见 `^C`，尚未完成全部验收。相同运行的 Windows 开发应用、AOT 应用及模板 PostgreSQL 检查已通过，SQLite 与 MySQL 候选检查也通过。保留失败原件后取消剩余 macOS 分组，未进入候选草稿、子仓 tag 分发或 Release 公开；取消项不计通过。安装测试使用 20 秒内层预算，但原报告未记录内层超时状态，不能仅凭 `^C` 断定根因，后续用原 ZIP 定向测量。

Windows 原候选 ZIP 的 SHA-256 为 `41f373594347b734c6a98c8dd121511ae3b9540149a8dce458b66fb7b05176bf`，程序 SHA-256 为 `a2b9fb07f3d664c30a500c8e0b437478110906fac79047ecf25fda74d412ebe6`。原 `windows-native-evidence` 附件摘要为 `3cf4ef3fbe82c1637cbb074640f49d39234ae7a1208d682f84b7e786658335f7`，下载后按 GitHub 记录回读核对；诊断不重编译或替换这些原件。

[原候选定向测量](https://github.com/zoujingli/typeapp/actions/runs/36235794593)复现了相同故障：20 秒预算在 20.218 秒触发内层超时，退出码 `-1073741510`，标准错误为 `^C`。仅调整等待预算后，同一程序在两个新建空库分别于 22.145 秒和 22.056 秒正常退出，两次均核对 83 个前端文件摘要；数据库采样没有锁等待。数据库实例及目录精确清理通过。修复提交 `4197eeb200251b6dd4f9dae7ac45125239e3038b` 将候选初始化统一到现有应用测试的 30 秒预算，并在成功报告和失败消息中记录内层退出、耗时及超时状态；原 RC3 标签保持不变，测量不能替代完整发布验收。

macOS ARM64 原候选归档 SHA-256 为 `f8c7cecbbff41c718908bf860e36c1e9084da1932eaf1af190c761f7e8fdf24e`，程序 SHA-256 为 `0744b9862cdaa39bd8dc0cfe35549ef61c689acac8dc1047e9b5181f54830e3a`。下载后直接解包，没有重新编译。隔离目录禁止读取主仓业务源码、Composer 与 SDK，并禁止执行 PHP/编译器；安装产生的 83 个文件逐项核对大小和摘要通过。全部文件的 GET 正文摘要、HEAD 空正文及 Content-Length、MIME、ETag 和缓存策略通过，首页 HEAD 和真实 `/public/site` JSON 也通过。

同一程序的浏览器补验通过平台及客户登录/退出、租户工作区、站点默认值、设置保存后刷新回读，以及平台角色新增、修改、查询、真实 API 删除和页面刷新确认。浏览器没有运行时异常，保留 HTTP 结果、操作回执及页面截图。这是本机 macOS 27 的功能补验；完整 dyld 部署审计仍因系统缓存与 CI macOS 15 不同而失败，不以页面成功覆盖该限制。

当前交付为包含原生运行库的目录归档。前端编入主程序，在 `app:install` 或 `web:install` 时安装到应用根下的 `public/`；普通启动不释放资源。完整静态单程序目标仍未完成，外部数据库及其他已配置的业务服务仍需准备。RC 不是稳定版本。
