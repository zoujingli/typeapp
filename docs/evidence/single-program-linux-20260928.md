## 真实失败与修复

首次制备缺少 PostgreSQL 生成源文件所需的 `flex`，已加入工具预检与 CI 依赖。随后真实 embed 链接暴露 Swoole 内置 nghttp2 与 curl 使用的系统 nghttp2 重复符号；改用 Swoole 官方 `--with-nghttp2-dir` 开关，让两者共用同一静态归档，保留 HTTP/2 功能。

链接成功后，审计误拒绝 glibc 的 `ld-linux-aarch64.so.1`。`readelf` 和发行版文件归属确认它是系统加载器；构建门禁现在仅接受 x64、ARM64 两种受支持架构的准确加载器名称，仍拒绝第三方共享库。修复后真实 embed 探针及上述全应用部署均通过。

旧容器的 AppArmor 限制曾阻止 namespace 挂载。新建本任务专属验证容器并通过真实隔离正反探针后才执行应用验收；没有取消应用的源码隔离检查，也未使用本机业务数据库。
