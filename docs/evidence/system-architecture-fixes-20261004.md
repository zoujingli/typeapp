# 配置与运行闭环修复验收

日期：2026-10-04。开发基线：`cc68d26`，分支 `main`。本记录承接[架构审查 A1—A8](system-architecture-audit-20261004.md)，保存新实现与本轮结果；历史审查和公开 RC14 的源码、产物及结论不改写。本轮不推送、不发版，不替换本机业务站点。

## 实现与复用

| 发现 | 复用入口与本次修改 | 明确边界 |
| --- | --- | --- |
| A1 配置预检 | `Settings` 共用角色预检和实际 `RequestPolicy`、`RequestLimits`、`HttpControl`、`DeploymentBudget`；管理保存与检查均复用 | 离线预检不连接、不建库；最终生效快照查字段组合，被覆盖的文件值单独查类型；恢复入口保留修复错误进程覆盖的能力 |
| A2 生产诊断 | `ApiErrors` 始终输出受控原因；`RequestLog` 加入耗时、结果及真实构建身份 | 不记录原始异常消息、SQL、参数或凭据；开发权限只增加有限帧，原生异常不保证 PHP 文件行号 |
| A3 调度停止 | `ApplicationScheduler` 复用 `ProcessSignals`、`Cancellation` 和 `Scheduler::stop()`；事件循环分发 Windows 控制意图，命令空闲检查间隔至多 50ms | 停止不撤销已完成外部效果；失锁保留未知状态，由接管者记为 `interrupted`；Windows 实际控制事件仍需验收 |
| A4 部署预算 | HTTP 线程、池与总额分开配置；数据库工厂覆盖应用角色及迁移连接，Redis 管理器各用途共用分额 | 同线程多管理器须显式共用预算对象；实际副本、进程与线程不得超过声明；MQTT 专用持久连接及其他直接连接另计 |
| A5 业务就绪 | `HttpReadiness` 与请求共用数据库管理器，检查迁移、兼容、恢复和安装身份；探针也经过 Host/代理策略 | 每执行者最多两秒一次，一秒作用域且不等待池额度；并发只读取五秒内的完成值；存活不探依赖，HTTP 不探后台可选 Redis |
| A6 应用升级 | `ApplicationUpgrade` 接入既有迁移锁和前后置校验，要求显式停写与非空普通备份文件的匹配摘要；修正初始化提示 | 只接受当前安装谱系，已知 101 可作为增量；未知版本、摘要变化及未核对中断明确拒绝；不自动停集群、不宣称备份可恢复或跨资源原子性 |
| A7 本地文件 | `LocalFile` 复用到日志、调度状态与备份检查，明确 Unix 和 Windows 盘符语法；保留延迟日志失败统计和 `TYPE_SCHEDULER_STORE` | 拒绝 URL、UNC、设备、链接与越界；父目录须受信任；Windows 实际文件系统行为不能用 Unix 字符串检查代替 |
| A8 无调用者配置 | 移除物联中心旧通用 Redis 缓存字段，旧启用开关始终返回 `feature_unavailable`，表单不允许启用 | 通知、导出与调度用途继续保留；独立应用可按需求接入 type-cache，不擅自为物联业务添加缓存 |

新增生产职责仅为应用升级门、每执行者就绪状态，以及多调用者共用的本地文件边界。没有新增容器、网络驱动、线程池或运行时源码加载机制。通信、定时与协程继续使用固定 Swoole 的原生机制，生产实现继续全量 TypePHP 编译。

## 验证入口

`tests/Unit/ArchitectureRuntimeTest.php` 在公开配置与组件接口验证非法配置拒绝、管理保存保留原文件、未选角色不引入依赖、生产日志脱敏及就绪/存活分离；`tests/Unit/LocalFileTest.php` 通过实际文件验证链接拒绝和锁冲突。完整 PHP 契约套件本轮通过 **193 tests / 15,427 assertions**；随后按职责拆分文件测试，并定向复验两组，PHP 通过不替代原生行为。

`tests/application-runtime.php` 为本轮三库和 Redis 建立专用前台进程，从含空格应用根的不同工作目录调用实际程序。可选旧版目录由公开发布清单约束，每个程序在执行前核对摘要与机器格式。升级夹具通过真实 HTTP 创建账号会话、产品、模型、设备和待处理导出任务；停写后备份，再执行新程序升级，逐表核对完整行内容摘要，并确认旧会话、设备和待处理任务仍可读取。

人工移除 `101_app_broker_operation_recovery` 的用例只用于已知增量与恢复门的故障验证，不能称为真实历史 100 版本升级。`running` 状态通过公开 `migrate history/recover` 核对；备份文件摘要错误必须在迁移写入前拒绝。

探针测试撤去必需表或改变迁移状态，检查 `/readyz` 503、`/livez` 200 及恢复后的 200；通过真实查询故障核对生产 500 的请求关联、构建身份和 SQL 脱敏。调度先观察真实 Redis 的 `running`，再发送停止信号或移除本轮专属租约，检查退出码、持久结果和接管后的中断记录；不靠固定休眠推断任务已运行。

`tests/iot-identity-databases.php --app --no-source` 继续验证同一最终程序的三库身份业务与无源码部署。主程序、构建清单、原始日志及新测试脚本的身份单独保全，不能以某次中间产物通过替代最终产物。

## 诊断保留与未验证范围

- 原生 HTTP 探针首次验收暴露 `ResponseEmitter::emit()` 漏传第三参数；PHP 默认值掩盖了 TypePHP 的严格调用检查。改为显式传入后，以同一真实 HTTP 入口复验。
- 文件校验最初提前拒绝缺失父目录，改变了日志的延迟失败契约。构造恢复为语法校验，打开前后做完整检查，既有 `log-failures` 及新链接拒绝断言复验。
- 一次编译期间构建输入变化，身份门禁拒绝该候选；不将拒绝候选标记为可交付产物。后续冻结输入重新生成身份并编译。
- 独立调度消费暴露 macOS 系统临时目录的链接别名。示例只对操作系统提供的默认目录解析真实位置，测试为自己创建的目录取得真实路径；显式用户状态路径继续拒绝链接。修复后保留原失败与命令复验日志。
- 本轮本机为 macOS ARM64，使用开发 embed 及共享运行库完成应用 AOT；这不是新的四平台 × 三 profile 静态 Release 验收，也未改变单文件生产交付目标。
- Windows 文件、锁、只读目录、控制事件和其他平台运行结果需通过对应原生环境补验。新代码不因 RC14 历史矩阵成功而自动获得这些结论。
- 多角色滚动峰值、全协议故障组合、真实设备容量及吞吐/CPU/RSS 对照没有在本轮重新执行；不能据本轮可靠性修复宣称性能提升或全系统验收完成。
