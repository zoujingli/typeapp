# TypePHP 0.9.3 升级验收

2026-09-24 将构建基线从 TypePHP 0.9.0／PHPX 2.9.0 升级到 TypePHP 0.9.3／PHPX 2.9.2。PHP 保持 8.5.10 ZTS，本轮原生验证平台为 macOS ARM64，使用已有的受控 Swoole 6.2.1。准确提交与依赖约束见根 `composer.lock`、`toolchain.lock.json` 和模板锁文件。

## 实现范围

复用 `TypephpCompatibility`、`PhpxThreadSource` 与现有线程 runtime 接缝，核对上游源码并更新摘要门禁，重新编译 PHPX。新版启动签名增加 `pre_shutdown`；本仓应用在 PHP 模块启动前登记为持久模块，枚举 AST 常量由生成的 MSHUTDOWN 清理，不重复调用临时模块路径的回调。线程消费者增加枚举 case 类常量与请求重建检查，生命周期细节见[已编译业务线程](../development/compiled-business-threads.md)。

编译器显式使用 `CompilerRuntime::source()`，让增量指纹包含实际编译器源码。上游新增的匿名类 opcode／eval 路径不符合本仓全量 AOT 要求，构建入口明确拒绝，要求使用具名类；`tests/build-errors.php` 通过真实编译入口验证拒绝行为。

组件声明、独立消费者、应用模板、第三方声明与 Windows PHPX 源码准备入口同步升级。Windows 仍复用旧发布包中的 PHP 8.5.10 SDK，只升级 Composer 编译器和重新构建的 PHPX；不以下载最新 SDK 隐含升级 PHP。

## 正确性与产物

- Composer 清单检查、格式检查、基础语法与文档检查通过；PHPUnit 85 项、2938 断言通过；11 个构建拒绝场景通过。
- 独立线程消费者全量 AOT 后移除生产源码运行通过：双线程隔离、非零返回、退出、八次重建、枚举 AST 常量，重复三轮。
- 独立 HTTP 线程消费者在禁止读取源码的环境运行通过：双线程 HTTP、逐请求清理、额度、退役与重建，以及监督停止、信号、部分启动、异常退出和原生阻塞回收。
- 完整应用编译 255 个生产源码输入、21 个生产包，共 271 个编译单元。产物 build id 为 `c2702a2aca80c8b009825167dff6fcff3feda05b363b78819067437e8685253f`，SHA-256 为 `2b31371a229712d62d097a138ced043b7f31ef6d6f9e30cace867d3a7531e22b`。
- 同一完整产物分别通过 MySQL、PostgreSQL、SQLite 无源码身份 HTTP 验收，检查数依次为 507／504／507。macOS 内核策略拒读业务、组件、依赖与生成源码，并核对策略对子进程生效；服务退出码为零，三库测试实例正常关闭。此项使用目录运行包，证明的范围是无源码运行。

这些产物仍依赖共享 PHP、PHPX 和扩展，不能作为“不释放运行库”的静态交付证据。静态方向的源码依据和实际链接阻点见[完整静态链接可行性](../development/static-runtime-feasibility.md)。

## 性能对照方法

旧基线由源码 `82285b3e96e6d171dceebfbb2d8fd8b95e688752` 的归档独立安装并重新 AOT，不使用业务已经落后的历史程序。288 个第一方生产 PHP／原生源码文件与新版逐个 SHA-256 比较一致。旧应用 SHA-256 为 `48a034efb207646eb20f0ea28b31426e5e8ff77f0b2a2bedc1bdca984b31aacd`。

新旧版本使用同一 PHP SDK、Swoole、系统工具和测试控制器；变化输入为编译器、PHPX 及本次构建适配。完整应用比较短 JSON、三库 CRUD 和真实 50ms 数据库锁等待；每个版本／数据库三轮，每类预热五次、测量三十次，并发一。三库使用独立测试实例，MySQL 8.4.11、PostgreSQL 17.11。文件流使用相同独立消费者，每轮预热五次、下载一百次 1MiB 固定文件，校验状态、长度和摘要，新旧顺序交替，共三轮。

应用 CRUD 按公开用户管理接口执行创建、读取、更新与停用，含真实密码散列成本；短 JSON 也经过认证和数据库读取。慢依赖真实持有行锁／SQLite 写锁，SQLite 按接口语义允许 BUSY 后核对无写入并由客户端重试一次，其余驱动等待行锁。

延迟记录 p50／p95／p99，另记录整个测量窗口的操作速率、服务进程树 CPU 与采样 RSS。窗口包含控制器采样和慢依赖准备成本，不能把该速率当作服务器最大 RPS；RSS 是采样最大值，CPU 来自系统进程计时。文件流与应用使用各自相同 HTTP 入口分别对照，不混算。

本机已测正确性、线程额度及资源回收均通过，测量期间没有持续内存增长或资源额度拒绝。结论限定于上述负载：尚未确认稳定性能退化，不宣称性能提升、峰值容量或跨平台等价；微小差异与长时间压力仍需专用环境测量。

## 本地证据与资源回收

任务证据根为 `build/typephp-upgrade.eFwiPE`。`same-source.json` 与 `file-same-source.json` 保存同源输入摘要，`measure.py`、`measure-followup.py` 保存调用协议，`measurements.json`、`measurements-followup.json` 和 `comparison.json` 保存全部样本及比较。三库无源码总报告的原始标识为 `iot-identity-databases-e8ecf3801c46`，各项原始报告、线程证据与构建身份集中保全到任务的 `evidence/`。

本轮已回收重复 Composer 安装、旧版对照程序、测试运行包、数据库数据、编译中间文件与本任务生成的完整应用缓存。`cleanup-evidence.json` 记录保全文件摘要与回收项。保留新版 `app/type-app` 及其资源／运行配置、重编译的 PHPX 2.9.2 源码／头文件／库和隔离 PHP 测试入口，用于后续原生验证；原有共享 SDK 和缓存未清理。

## 平台与交付边界

本轮未重新执行 Linux／Windows 原生验收或性能对照，历史平台结果保留原工具链身份，不自动转为新版成功。上游发布归档缺少 Composer 声明的 `bin/tpc`，安装会提示跳过该入口；本仓实际 `type-compiler`／`tpc.php` 路径已通过原生构建。

升级不代表完整协议、故障矩阵、单程序封装或全部平台已完成。后续先解决静态 PDO hook 的符号归属和非系统依赖闭包，再验证无 SDK、无源码、无外部非系统库且启动不释放库的真实运行。
