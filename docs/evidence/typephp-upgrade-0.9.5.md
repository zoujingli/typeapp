# TypePHP 0.9.5 / PHPX 2.9.4 升级

2026-10-20 在 macOS ARM64 完成当前主仓工具链迁移。升级基准为 `4f949f90dd627960e5e48eb67f795017752c82bf`，新端使用本提交的生产源码与构建适配；编译时尚未提交，构建报告记录各输入摘要。未发布新版本，RC14 的程序、标签和验收结论保持原身份。

锁文件、构建组件、应用模板、SDK 制备脚本及源码摘要门禁同步更新。PHPX 在独立源码副本上应用既有线程/协程、finalizer 和字符串写时复制适配，再重新编译；兼容补丁未直接改写共享 vendor 或旧 SDK。

TypePHP 已修复嵌套对象默认值的临时作用域，删除项目的 `parseParamDefaultValue()` 覆写，直接使用上游实现。默认值仅在缺参时求值、提升属性声明作用域等尚未被当前发布版本覆盖的适配继续保留。

完整应用首次编译在 MQTT 的 `$omitTopic ? '' : $this->topic` 失败。最小输入可在原始上游入口复现 `const String` 与 `Variant` 不兼容；把空串换成非空串或把属性先存入局部字符串均可编译。兼容层据此在字符串三元分支的原求值位置复用上游转换，保留共享空串、惰性及临时量清理，未修改 MQTT 的业务语义。回归先失败再通过，规则与撤除条件见[语法基线](../standards/typephp.md#字符串三元分支的编译适配)。

## 同条件性能对照

旧端由基准提交的普通源码快照构建，没有创建 Git worktree。新旧端的业务源码、生产包集合、前端资源、应用配置、PHP/Swoole、AppleClang 21.0.0.21000334 及 PHPX Release 编译选项一致；变化为 TypePHP、PHPX 及对应构建适配。旧端程序为 35,232,776 字节、SHA-256 `4e0358545da477421403691841fba6710fd99c17df3fd2c98693f32078450ef4`。新端共享运行库产物体积增加 2.10%，静态单程序体积本轮未测。

应用复用 `tests/application-benchmark.php` 的短 JSON、CRUD 和真实 50 ms 数据库锁等待。每个版本/数据库测量三轮，每类预热 5 次、正式 30 次，并发 1；先旧后新及先新后旧各做一轮完整三库对照，使用原 `tests/benchmark-compare.php` 判据。文件流使用同源码独立消费者和 Swoole HTTP，六对测量交替顺序，每轮预热 5 次、正式下载 100 次固定 1 MiB 文件，并核对状态、长度和摘要。

首轮九组应用负载均未触发区间分离信号。SQLite 短请求的窗口吞吐波动伴随采样耗时变化；PostgreSQL 短请求的 p95 中位数从 6.043 增至 14.283 ms，但逆序为 8.035 → 7.145 ms，没有持续复现该差异。

逆序只有 SQLite CRUD 的窗口吞吐触发信号，中位数下降 1.29%，同时请求 p50/p95 和服务 CPU 中位数降低；新端窗口内采样耗时为 0.067–0.309 秒，旧端为 0.061–0.116 秒。随后仅对 SQLite 做六对交替测量，继续使用原负载、预热、样本数、采样器和比较函数，三类负载均未再触发信号。保留首次信号与所有后续样本，未修改判据或剔除慢样本。
