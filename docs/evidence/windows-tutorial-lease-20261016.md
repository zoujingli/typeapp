# Windows PostgreSQL 教程租约诊断

RC16 的 PostgreSQL 教程程序在普通运行中通过，在无源码部署验收中于 `catalog relay` 返回 `internal_error`，随后 Job 验收受未消费的遗留消息影响。该批次未公开，原始结果不因后续修复改写。

## 原始身份与复演

- [RC16 发布运行](https://github.com/zoujingli/typeapp/actions/runs/38821654510)，源码 `1386d9af43ba746b8804111159cc8e4d358abecf`，失败任务 `116737112710`。
- 原教程 EXE 为 33795709 字节，SHA-256 为 `2704318aad29041e0893acffba82ce4320aa96bd53a68d827af55c363af55346`。
- 原证据 Artifact `12017197857` 的下载 ZIP 摘要为 `73f1db83f9b4f851e43fa780bb0e94232d7783c564ab5780b6691f697d1b6790`。
- [原 EXE 普通及隔离复演](https://github.com/zoujingli/typeapp/actions/runs/38832075930)各执行三轮。普通运行也复现一次 relay 失败；该次耗时 0.610 秒，观察时领取租约已经过期 188 毫秒。随后新领取成功，说明失败并非隔离权限特有。

## 单变量对照与结论

[租约对照运行](https://github.com/zoujingli/typeapp/actions/runs/38832755630)继续使用同一原始 EXE。每轮创建专用 PostgreSQL 数据库和 Redis 命名空间，均在相同 Windows 受限令牌环境运行；数据库触发器为领取增加 350 毫秒延迟，只改变领取租约长度。

| 条件 | 两轮 relay 结果 | 消费结果 |
| --- | --- | --- |
| 教程原 250 毫秒租约 | 两轮的两次独立 relay 均退出 1；记录停留在 claimed，租约已过期 | 三次消息产生一次效果，接受凭据未登记 |
| 30 秒租约，同样的领取延迟 | 两轮首次 relay 均 `accepted:1`，随后均 `accepted:0` | 两次消息产生一次效果，接受和消费正常完成 |

两组的 Job 非法输入、取消和清理恢复均正常：尝试次数分别为 `[1,2,3]`、`[1,2]`、`[1,2]`，效果数分别为 0、1、1。专用数据库、Redis、受限权限和运行目录均已清理。对照 Artifact `12017937968` 的下载 ZIP 摘要为 `2d8e1d67bad5011b6c23b715b6f5b5c8638ce18adbc913af6a65390ed088f6e8`。

根因为教程把 Store 的默认 30000 毫秒租约压缩到 250 毫秒，领取事务、Redis 投递和接受凭据登记可能无法在有效期内完成。框架拒绝过期 token 的行为符合合同；本次不放宽检查、不重试未知提交、不调整队列语义。

## 修复与验证边界

教程装配和迁移构造沿用 Store 默认租约。故障演练的回归通过公开领取结果在 35 秒预算内等待，到期后核对接受凭据、两次消费及唯一效果；命令异常仍立即失败。使用说明同步等待标准租约，不再建议用短租约缩短演练。开发入口的整套教程等待预算与既有原生教程统一为 120 秒，容纳新增的实际租约等待；普通模板仍为 45 秒，各业务命令的 15 秒预算不变。

首次本机检查使用 PHP 8.4.14、Swoole 6.2.2，在 Composer 安装时被 Redis 扩展 6.2.0 拒绝，组件要求 `ext-redis ^6.3`，没有执行教程行为，不计为通过。

随后复用既有锁定 SDK（PHP 8.5.10 ZTS、Swoole 6.3.0RC1、Redis 扩展 6.3.0），以源码 `59fcb0fbfb46f1fe80824ed889b60bf92a519fd1` 执行独立 SQLite 教程的 PHP 入口，11 组公开行为全部通过。覆盖迁移、HTTP CRUD、缓存、Outbox 重复消费、Job 取消和清理、Task 游标以及真实 HTTPS；Redis 服务为本机独立的 8.8.0 实例，临时服务、消费者和数据均已回收。

[修复后的 Windows PostgreSQL 教程](https://github.com/zoujingli/typeapp/actions/runs/38833958325)以同一源码 `59fcb0fbfb46f1fe80824ed889b60bf92a519fd1` 全量编译 271 份生产源码，独立消费者及无源码部署均通过。新 EXE 为 33795709 字节，SHA-256 为 `8209d8d3f17f21261c08ec52be821e797c9a9283de0c104c9979cd2ba9b6bec5`。受限部署中的整套教程耗时 56.85 秒，预算 120 秒，退出 0；smoke 和 catalog 服务均正常停止，无超时或强制终止。

同一程序通过源码与 SDK 拒读、外置 ini 忽略、数据库 profile 拒绝、只读程序目录、不同工作目录和普通启动不写文件检查，核验 52 份许可材料。Artifact `12020911198` 的下载 ZIP 共 14368561 字节，SHA-256 为 `4e2527ea3af68b2cdeef0a7e90b85c71a588efb92dfe7c651be324314986ebc5`；程序、锁文件、消费者、教程、部署和构建记录的内部摘要均已回读一致。

该运行是固定候选的单平台、单数据库定向验收，没有公开新版本。正式发布仍须用最终源码及程序完成四平台、三数据库教程矩阵；原 EXE 对照和本机 PHP 结果分别保留原验证边界。
