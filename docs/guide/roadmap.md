# 当前能力与实现规划

TypeApp 以 TypePHP 编译生产代码，以 Swoole 承担通信与基础并发，通过 Plugins 组合应用能力。本文将代码中已有的入口与尚未完成的交付要求对应起来；源码发布并不表示全部目标平台、协议义务和部署形态已经验收。

## 当前实现

- 已有 HTTP、TCP、UDP、MQTT、WebSocket 的入口与独立教程。HTTP 和 WebSocket 可以在同一服务、同一端口中分别处理普通请求和协议升级，接入方式见[WebSocket](communications/websocket.md)。
- Plugins 提供运行时、核心服务、三库 ORM、Redis、缓存、校验、日志、队列、调度、构建、测试及 MQTT 能力。MySQL、PostgreSQL、SQLite 按各自真实语义验证。
- 物联中心具有平台账号、客户账号、租户成员与 RBAC；Broker 使用独立管理身份域。组件与物联业务分别维护。
- 构建工具已有生产输入清单、依赖身份、AOT 构建、携带运行库的目录包和归档能力。单程序封装仍待完成。

## 推进顺序

先完成 Swoole 通信与执行入口收敛，固定工具链并验证调用者；随后完成单程序封装和标准项目生成，执行独立消费及目标平台组合验收。UI 与业务完善可按现有稳定接口推进，发布后的缺陷修复继续同步当前说明。

每项结果以实际命令退出、协议响应、业务状态和资源释放为判断依据。PHP 行为检查、AOT 编译成功、原生行为通过和完整交付分别判定；缺少运行结果的能力明确保留待验收状态。
