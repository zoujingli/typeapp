现有能力的需求与入口见[基础能力与验收](capabilities.md)，技术边界见[系统架构](architecture.md)。本文只维护尚未闭合的交付要求；有历史产物记录的结果不自动适用于当前源码与工具链。

## 标准框架

本轮新增[版本发布](releases.md)链路和[前端内嵌安装](deployment.md#前端安装与更新)。RC4 的四平台完整矩阵及原候选已通过，跨仓发布的索引检查发现缓存接口选择错误；修正后准备以 `v1.0.0-rc.5` 重新验收，尚未公开。四平台最终附件、16 个子仓 tag、16 个 Packagist 版本和 17 个 Release 全部核对后，才算完成发布闭环。此前候选保留原身份，不能算作公开发布。

## ORM 补齐顺序

模型操作与协程能力按以下顺序收口，复用现有 ModelQuery、驱动、作用域和消费者，不增加另一套连接池或调度器。已有接口及有意边界见[常用能力边界](database.md#常用能力边界)。

| 顺序 | 当前缺口 | 完成条件 |
| --- | --- | --- |
| 1. 所选驱动的协程前置校验 | `enableIo()` 跳过不存在的 PDO hook，驱动连接只检查 PDO 扩展；版本正确仍可能缺协程 I/O 能力 | 在实际选用的协程数据库路径校验构建能力及 hook，缺失明确失败；不因未选驱动阻止启动，保留同步工具边界，并验证真实等待能让出 |
| 2. 模型聚合 | ModelQuery 只有 `count`，模型自身 SUM、AVG、MIN、MAX 缺失 | 沿用字段映射、租户、软删除和读路由；明确空集、null、精确数值及三库实际列类型的返回/拒绝语义 |
| 3. 模型批量新增与冲突写入 | 底层 Query 有 SQL 能力，模型层没有对应完整契约 | 统一赋值与类型、租户键、唯一冲突、软删除、版本、事件和返回语义；并发下无部分写入或跨租户更新，不把先查后写当作原子 upsert |
| 4. 跨租约物理复用 | MySQL/SQLite 尚无完整重置；消费者已记录污染场景的 backend 身份并断言退役，纯 CRUD 跨租约复用仍缺独立身份观测 | 补齐纯 CRUD 身份断言及两种驱动的重置，证明污染、泄漏事务、断连、取消和凭据代次安全，再验证同负载吞吐/延迟；不能仅去掉关闭逻辑 |
| 5. 提交未知与故障组合 | 默认平台矩阵和公共分发集成已通过；MySQL 提交后回调中新事务 UNKNOWN 仍缺对应同产物断连验证 | 复用真实提交故障装置，验证未知事实、对账与资源收尾；不把其他数据库的延迟外键结果当作 MySQL 同场景通过 |

自动时间字段、模型重新加载、关系写入助手及集合恢复属于便捷入口，按实际业务需求补充。多态/穿透关系和 Schema DSL 不作为已有基础能力，也不因缺少同名接口引入动态运行机制。业务领域迁移至 Model 是独立接入工作，不用 ORM 组件通过替代应用验收。

## 推进顺序

1. **打通完整静态产物。** 在已通过的工具链基线上解决静态构建的 PHP PDO/Swoole 驱动符号冲突，闭合 PHP/PHPX/扩展依赖、资源与许可、内部配置和直接启动入口。通过无源码、无 SDK、无外部非系统库且启动不释放库的验收后，才能按单程序交付。
2. **补齐 ORM 公共能力。** 按上表完成所选 PDO hook 前置校验、模型聚合、批量写入、MySQL/SQLite 重置复用及提交未知专项，保持租户、事务和协程资源语义。
3. **扩展角色与平台验收。** 复用已通过的四平台默认矩阵，补齐协议、故障域、隔离强度与性能/容量对照；新增结果使用真实分发组件并保留准确身份。
4. **完成业务成品出口。** 沿用现有身份和公开接口，收敛物联业务、Vben 管理体验及同源生成，验证初始化、升级、重装和恢复。

基础能力可沿已有接口独立推进；单程序部署必须通过第一项的专门验收。UI 和业务缺口保持自己的验收责任，不能用框架组件测试代替。

每项结果以实际命令退出、协议响应、业务状态和资源释放为判断依据。PHP 行为检查、AOT 编译成功、原生行为通过和完整交付分别判定；缺少运行结果的能力明确保留待验收状态。
