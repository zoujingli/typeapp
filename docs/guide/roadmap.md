# 实现规划

现有能力的需求与入口见[基础能力与验收](capabilities.md)，技术边界见[系统架构](architecture.md)。本文只维护尚未闭合的交付要求；有历史产物记录的结果不自动适用于当前源码与工具链。

## 标准框架

框架任务只交付可独立消费的通用机制。应用负责认证、授权和业务状态，业务接入按下节单独验收；框架组件不依赖物联中心的账号、成员、角色或设备模型。

| 工作 | 当前代码边界 | 完成条件 |
| --- | --- | --- |
| 当前执行作用域 | 已接入 HTTP、WebSocket 公开回调、MQTT Broker 事件、生成 CLI、队列、调度和受管子任务；TCP/UDP 示例显式绑定。MQTT 的隔离、异常恢复、停止信号与晚完成已通过 macOS ARM64 PHP/AOT 独立消费及无源码边界验证 | 独立持久处理角色按实际装配继续核对；协议与后台业务的完整平台结果分别验收，见[当前作用域](https://github.com/zoujingli/typeapp/blob/main/docs/development/managed-tasks.md#当前作用域与应用绑定) |
| Model 自动连接与主从路由 | 生成模型已提供无连接 `query/search/find/create`，`Db` 提供无连接同库事务；查询执行时按读写意图选择主从，事务外写后仍默认读从。macOS ARM64、Linux ARM64、Windows x64 的同提交三库独立消费、AOT、无源码和上下文矩阵通过；macOS 主从专项 PHP/AOT 通过 | 完成远端组件分发消费及其他平台独立主从端点验收；全部协议入口作用域和物理 PDO 复用分别收口。接口与边界见[模型连接与主从路由](https://github.com/zoujingli/typeapp/blob/main/docs/development/model-connections.md) |
| 物理数据库连接复用 | PostgreSQL 使用完整重置后复用 PDO；MySQL、SQLite 无完整重置保证时安全关闭。macOS ARM64、Linux ARM64、Windows x64 的同提交三库 PHP/原生消费覆盖会话隔离、故障退役及凭据代次；macOS PostgreSQL 已完成同负载复用性能对照 | 完成其他平台负载对照；MySQL 标准 PDO 缺少完整重置接口，SQLite 完整重置未实现，完整三库物理复用保持未完成 |

| Swoole 通信与并发验收 | 代码已统一由 Swoole 承担 Broker、客户端、持久工作、设备授权和 CRL HTTPS；仍需按产物完成协议与平台组合验收 | 验证 TLS、QoS、保活、重连、取消、资源释放、持久确认和 CRL 更新，并记录同一产物证据 |

| SDK 与编译线程接入 | 已锁定 TypePHP 0.9.3／PHPX 2.9.2，并随构建组件提供四平台 Swoole 模块；各目标仍需匹配的 PHP SDK、线程/协程开关和生产扩展 | 完成新版 Linux/Windows 工具链、线程生命周期、协程降级与完整应用 AOT 验收，保留各次产物身份 |

## ORM 补齐顺序

模型操作与协程能力按以下顺序收口，复用现有 ModelQuery、驱动、作用域和消费者，不增加另一套连接池或调度器。已有接口及有意边界见[常用能力边界](database.md#常用能力边界)。

| 顺序 | 当前缺口 | 完成条件 |
| --- | --- | --- |
| 1. 所选驱动的协程前置校验 | `enableIo()` 跳过不存在的 PDO hook，驱动连接只检查 PDO 扩展；版本正确仍可能缺协程 I/O 能力 | 在实际选用的协程数据库路径校验构建能力及 hook，缺失明确失败；不因未选驱动阻止启动，保留同步工具边界，并验证真实等待能让出 |
| 2. 模型聚合 | ModelQuery 只有 `count`，模型自身 SUM、AVG、MIN、MAX 缺失 | 沿用字段映射、租户、软删除和读路由；明确空集、null、精确数值及三库实际列类型的返回/拒绝语义 |
| 3. 模型批量新增与冲突写入 | 底层 Query 有 SQL 能力，模型层没有对应完整契约 | 统一赋值与类型、租户键、唯一冲突、软删除、版本、事件和返回语义；并发下无部分写入或跨租户更新，不把先查后写当作原子 upsert |
| 4. 跨租约物理复用 | MySQL/SQLite 尚无完整重置；普通 CRUD 消费者报告未直接测量 backend 身份 | 证明会话污染、泄漏事务、断连、取消和凭据代次安全，再验证同负载吞吐/延迟；不能仅去掉关闭逻辑 |
| 5. 分发与平台验收 | 当前修复的本机结果不覆盖公开组件精确提交安装和所有平台；MySQL 提交后新事务 UNKNOWN 尚缺同产物断连验证 | 按同一源码完成三库独立安装、全量 AOT、无源码运行、真实提交故障及资源收尾，保留每次产物身份 |

自动时间字段、模型重新加载、关系写入助手及集合恢复属于便捷入口，按实际业务需求补充。多态/穿透关系和 Schema DSL 不作为已有基础能力，也不因缺少同名接口引入动态运行机制。业务领域迁移至 Model 是独立接入工作，不用 ORM 组件通过替代应用验收。

## 业务应用

物联中心使用框架公开接口，以下任务不纳入 ORM 组件内部，也不作为其他应用独立安装框架的前置条件。

| 工作 | 当前代码边界 | 完成条件 |
| --- | --- | --- |
| 身份与租户业务接入 Model | 账号、会话、租户、成员、角色及纯绑定关系已接入 Model，权限码集合由授权事务受控维护；后台导出重验持久来源后绑定租户。macOS ARM64 三库 PHP 与同一完整应用 AOT 产物的无源码运行通过，包含角色、管理员替换、消息伪造和权限失效；静态检查限制普通实体绕过 Model | 其他平台业务同提交验收独立推进；保持授权、资料版本和模拟来源语义，见[双端身份](https://github.com/zoujingli/typeapp/blob/main/docs/development/iot-identity.md) |
| 其他领域 Model 与业务 CRUD | 设备、产品、Broker 资源等仍需按领域整理数据入口 | 逐领域完成模型与业务行为，限制表查询例外；保持数据归属、授权及事务边界 |
| 标准物联项目分发 | 独立应用模板与完整主仓业务生成范围分别维护 | 物联成品从同一业务、前端与配置源生成，使用公开组件安装并验证初始化、升级与重装；通用模板不默认携带物联业务 |
| 双端管理体验 | 已使用 Vben BasicLayout、菜单和主题；列表、搜索与抽屉仍有应用封装，分组菜单未完整对应嵌套路由 | 按锁定 Vben 能力完善认证布局、用户入口、表单/表格/抽屉，统一分组面包屑和详情父级关系；逐类验收权限、深链接、亮暗主题和窄屏 |
| 站点信息与默认值 | 空库安装保存品牌和界面默认值，整页保存有权限、版本与审计保护；时区、站点说明和个人默认值消费仍有缺口 | 统一业务时间与导出的时区语义，接通站点说明展示、个人覆盖及两类恢复默认入口；按实际部署需求补独立备案号、联系及页脚字段，不虚构默认资料 |
| 业务组合测试对齐 | 部分恢复、接入及运维测试仍引用已移除的身份或命令入口 | 将装置统一到当前双端身份与命令，保留持久确认、隔离、恢复和故障断言，再执行完整组合回归 |
| 全平台应用完整验收 | macOS ARM64 已完成完整应用 AOT 和三库身份无源码运行；Linux ARM64 已通过独立 ORM 消费，Windows 完整应用及三库仍待实际运行 | 按各平台同一源码与实际产物完成全量业务编译、业务通信、存储、故障恢复与无源码部署，不用组件验收替代成品应用验收 |

## 推进顺序

1. **稳定编译与原生运行基线。** 复用 TypePHP 0.9.3、PHPX 2.9.2 和内置模块，完成新版 Linux/Windows 工具链、角色入口和真实 embed 验收。
2. **打通完整静态产物。** 先解决 PHP PDO 与 Swoole 驱动符号冲突，再闭合 PHP/PHPX/扩展依赖、资源与许可、内部配置和直接启动入口。通过无源码、无 SDK、无外部非系统库且启动不释放库的验收后，才能按单程序交付。
3. **闭合通用能力与独立消费。** 补齐 MySQL/SQLite 物理连接复用、协议与故障域验收，以及四平台当前工具链的三库和完整应用矩阵；使用真实分发组件验证。
4. **完成业务成品出口。** 沿用现有身份和公开接口，收敛物联业务、Vben 管理体验及同源生成，验证初始化、升级、重装和恢复。

基础能力可沿已有接口独立推进；单程序部署验收以前两项成立为前提。UI 和业务缺口保持自己的验收责任，不能用框架组件测试代替。

每项结果以实际命令退出、协议响应、业务状态和资源释放为判断依据。PHP 行为检查、AOT 编译成功、原生行为通过和完整交付分别判定；缺少运行结果的能力明确保留待验收状态。
