VISION & VALUE

连接只是起点，
可信业务才是目标。

建设统一的设备业务中心，将身份、模型、数据、控制与运营纳入同一套管理体系。让每一次上报有接收依据，每一条指令有结果记录，每一份数据有明确归属。

统一接入与管理

自研标准 MQTT 服务连接设备，产品与版本化物模型约定数据含义，统一管理设备从注册、启用到退役的完整生命周期。

独立协议组件 + 完整业务应用

BUSINESS APPLICATION

业务有明确的所有者

TypeApp 应用负责租户、产品、物模型、设备、可靠接收、遥测、指令、告警与审计。复用框架的 HTTP、ORM、校验、日志、Outbox、队列与调度能力。

应用校验业务契约；Broker 负责标准消息能力。生产 PHP 实现统一进入 TypePHP 全量 AOT。

贯穿各层租户隔离稳定业务身份有界资源可追溯证据全量生产 PHP 编译

Broker 可独立安装、独立进程运行，兼容范围按 OASIS MQTT 3.1.1 / 5.0 标准验收。设备业务采用 MQTT 5、JSON 与 QoS 1；标准客户端仍可交换合法二进制载荷。

04 /

BUSINESS FLOWS

每一步，都有业务依据。

上报是否被持久接收、设备是否真实执行、数据属于哪个组织，需要不同的证据。三条关键链路明确正常路径、异常处理与完成条件。

收到持久回执，才算可靠接收。

设备保留未确认原件。网络中断或回执丢失时使用相同业务身份重传，让重复到达与业务接收保持一致。

  1. 01

    设备持久缓存

    采样数据先写入本地缓存，保留跨重启稳定的设备、归属阶段和递增序号。

  2. 02

    标准安全接入

    经 MQTT 5 / TLS 上报，校验设备凭据和 Topic 权限，按 QoS 1 交付。

  3. 03

    平台持久接收

    验证身份、物模型和时间，持久去重，并取得 PostgreSQL 同步提交证据。

  4. 04

    返回业务回执

    平台返回独立持久接收回执；设备核对成功后清理对应缓存原件。

  5. 05

    业务数据可用

    独立推进当前值、历史、聚合与告警；处理可恢复，迟到数据按规则修正历史。

关键边界MQTT PUBACK 表示协议确认；平台持久接收回执表示业务持久接收。后续聚合或告警完成不作为清理设备缓存的前提。

控制看执行证据，未知继续对账。

平台受理、协议交付与设备执行分别记录。设备可能已经动作但回执丢失，因此缺少结果时保留“指令结果未知”。

  1. 01

    校验并持久创建

    核对租户权限与指令模型，持久保存指令 ID 和原始截止时间。

  2. 02

    在线有限发送

    默认有效期 60 秒，在第 0、10、30 秒最多尝试三次，离线控制拒绝。

  3. 03

    设备去重执行

    检查可信时间、期限及持久去重记录。同一 ID 不重复启动设备动作。

  4. 04

    核对执行回执

    设备报告执行结果，平台记录成功或失败；第 60 秒仍无结果则进入未知。

  5. 05

    查询与迟到对账

    第 60、120、300 秒自动查询，之后可主动查询。合法迟到回执补全结果。

关键边界查询结果不重新执行。重投沿用同一 ID 与原截止时间，且以设备具备持久去重能力为前提；创建新 ID 意味着新的设备动作。

设备可转移，历史归属保持清晰。

转移是一项双方确认的业务操作。先处理旧阶段的缓存、控制和权限，再形成新归属阶段，避免旧业务穿透租户边界。

  1. 01

    双方管理员确认

    源租户发起，目标租户接受，并匹配结构一致的目标产品与模型版本。

  2. 02

    冻结新控制

    停止创建新的设备动作，核对所有未完成指令及仍然未知的执行结果。

  3. 03

    排空与设备确认

    设备排空未确认上报，确认具备切换条件；条件不满足则保持待处理。

  4. 04

    隔离旧连接与授权

    失效旧凭据、连接、订阅、恢复会话及待投递消息，轮换为新凭据。

  5. 05

    激活新归属阶段

    新租户接收切换后的数据。旧遥测、指令和审计继续属于原租户。

关键边界结果未知、缓存未排空、设备未确认或旧会话未隔离时不切换。超时保持待处理，不静默强制成功或自动恢复旧授权。

05 /

SECURITY & OWNERSHIP

多租户协同，
每次访问都有边界。

以组织归属、人员角色与设备身份共同约束访问。授权检查贯穿接口请求、连接恢复、消息投递、历史查询和文件下载。

设备身份独立、可撤销

每设备独立凭据，生产使用 TLS 1.2 / 1.3，优先 1.3。凭据仅生成时显示，服务端保存不可逆验证值；轮换、吊销和禁用使旧连接及恢复会话失效。

租户归属与角色分权

设备同一时刻只属于一个租户。用户可加入多个租户，但每次操作都校验当前上下文；平台管理员身份不自动获得租户设备控制权。

限时支持、全过程追溯

跨租户支持由租户管理员授权，最长 1 小时、默认只读，控制等动作需单独授权。可随时撤销，敏感操作、授权变更与转移留下脱敏审计。

平台人员按当前角色与租户范围操作，不具备转授、租户管理或设备转移权限。菜单和按钮控制不能替代服务端授权校验。

06 /

RESILIENCE BY DESIGN

以持久事实，
应对不确定的故障。

生产以 Linux x64、应用与 Broker 多实例、PostgreSQL 严格同步高可用为基础。分别验证单节点故障、集中重连与独立备份恢复。

RECOVERY OBJECTIVES / 验收目标

≤ 60秒

单节点故障恢复

覆盖进程、主机、磁盘与单节点网络隔离，恢复可确认的业务接收。

0条丢失

已确认持久数据

限定单节点故障范围，对照设备已获持久回执的稳定消息 ID 验证。

≤ 5分钟

备份恢复 RPO

独立备份域与持续 WAL 归档，控制整站故障或误删除的数据恢复点。

≤ 4小时

业务恢复 RTO

包含授权核对，以及设备接入、查询和控制恢复；按目标数据量演练。

失去同步条件时停止成功确认；网络分区中，仅一致性成立的一侧继续确认。恢复旧备份后先核对凭据、成员授权与设备归属，再开放业务。

单节点恢复与整站灾备采用不同验收条件。通用框架保持 MySQL、PostgreSQL、SQLite 支持；本方案的生产同步高可用与容量目标以 PostgreSQL 验证。

恢复与授权正确性

核对已确认消息 ID、恢复时间与授权状态，防止旧凭据和转移前会话重新生效。

交付边界与协作条件

平台与设备侧共同交付

平台提供协议、标准客户端用例、模拟器和联调流程；设备侧提供适配固件、样机及责任方。真实设备、完整负载环境和独立备份域须落实并核验，模拟器不替代样机验收。TypePHP AOT 仍保留必要的 PHPX、libphp 与原生扩展运行依赖。

本次不包含的扩展能力

OTA、网关子设备、可视化规则编排、外部短信 / 邮件 / Webhook 通知，以及 WS / WSS、MQTT-SN、MQTT 3.1、私有设备协议、MQTT 5 增强认证方法和 EMQX 专有管理 API 不在本次范围内。通用框架的三库与正式平台支持义务继续保留。
