# 测试与质量检查

完整交付按[项目标准](project.md#100-全量编译门槛)核对全量源码清单、目标平台及真实行为；性能优化另外遵守[性能证据要求](project.md#极简与效率)。PHP 通过、原生编译通过和原生行为通过分别记录。

测试观察安装后的组件公开接口、显式生成入口、命令退出码和真实 HTTP 响应。选择实际驱动验证数据库语义，跨进程、Redis 和文件系统故障使用独立测试资源；不给用户数据库写测试内容，不用内部 mock 证明外部协议。

## 分层入口

- `composer cs-check`：PSR-12 与显式非 risky 格式规则，不能代替功能验证。
- `composer check`：PHP 语法及基础公开行为。
- `composer test:unit`：PHPUnit 的无外部服务契约套件，覆盖结构、配置、生成器和约束；测试结果与原生证据分别报告。
- `composer typeapp:test` / `composer typeapp:test-native`：标准应用的离线命令、迁移、用户 HTTP、单应用/多应用路由以及实际配置加载；各自只操作新建的专用测试数据库。
- 各组件 `test:*` / `build:*`：保留现有的真实三库、Redis、故障、独立消费和完整 AOT 验收，不为换测试框架删除已验证的场景。

具体脚本与参数以根 `composer.json` 为准。新增行为有对应可失败的断言；在已有命令、HTTP、生成代码入口测试，不把文件存在或生成文本快照当作真实业务执行。

## 重点规则

1. `.env` 测试只使用临时哨兵值；验证外部环境优先、空值/null、引号、类型和错误脱敏，不读取真实部署密钥。
2. 配置编译器拒绝任意函数/加载/执行，改变进程环境不能让生成源码夹带秘密。原始声明和生成结果纳入构建身份。
3. 缓存验证命中、null、期限、异常不写入和提交后失效；事务验证提交、回滚、外层事务和异常状态，不默认重试未知提交。
4. 任意应用层级由 Composer 映射证明；没有路由注解且未写入 `config/route.php` 的控制器不会成为公开入口。
5. 格式化后的代码仍经过原语法/行为检查和必要 AOT；vendor 与生成缓存不被批量重写。
6. 测试成功、失败或中断后均按[临时资源规则](project.md#主分支开发与临时资源)回收本次创建的目录、进程、数据库、容器和密钥；失败症状及必要原始证据先保全，完成报告写明实际清理与保留项。

## 工具链升级的性能验收

没有另行约定业务并发量或延迟指标时，升级前后在固定环境下比较同功能负载，覆盖短 JSON 请求、MySQL/PostgreSQL/SQLite CRUD、文件流及慢依赖场景。固定业务行为、数据与负载，明确记录工具链迁移所改变的输入，并按[性能证据要求](project.md#极简与效率)记录预热、重复次数、吞吐、延迟和资源消耗；不同 HTTP 引擎分别建立基线，不互相代替。

验收以正确性、资源不超过既定预算，以及相对旧版没有经重复测量确认的性能回退为门槛，不承诺跨机器统一的 RPS。缺少对应平台的可复现旧版基线时，明确保留该对照的未验证状态，不能用其他平台结果或一次偶然测量宣称通过。

提交按功能组织，使用带前缀的准确描述；实际运行的检查、跳过项和外部限制分别记录。当前交付状态以同一源码与产物的实际验证结果为准。
